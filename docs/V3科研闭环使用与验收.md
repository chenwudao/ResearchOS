# ResearchOS V3：科研闭环执行

本次实现前三个 P0 方向，围绕本机 Python 算法对照实验贯通「研究问题 → 可编辑计划 → 协议与预算审批 → 批量运行 → 结果分析 → 证据报告 → 人工确认 → 更新研究状态 → 下一轮计划」。保留 V2 的项目、聊天、论文、资源、目标和记忆功能。

## 从哪里使用

运行 `python scripts/start.py`，访问 http://127.0.0.1:8765。选择一个课题，在课题首页或资源库打开「科研闭环」。

1. 在「科研状态」填写核心问题、阶段、假设、障碍、下一步和决策，或输入研究目标让 DSH 检查实际项目资源并生成计划。
2. 在「实验工作流」创建算法对照示例，或导入自己的计划 JSON。示例会生成合成分类数据和真实 sklearn 脚本；不是预填指标。
3. 编辑计划，检查方法、数据划分、主指标、种子、样本预算、收益门槛、并发和时间预算。点击「确认协议与预算」，再「开始执行」。
4. 查看矩阵进度、每次尝试的命令、环境、退出码、stdout/stderr 和指标。可以暂停、取消，之后校验产物并续接。
5. 查看均值与标准差、配对收益、最差情形和门槛判断，下载 Markdown 报告、CSV 汇总、分析 JSON 和协议环境 JSON。
6. 核查结果后点击「确认结果并更新研究状态」。结果同步到结构化状态、目标、科研记忆和资源库。
7. 可手工修订下一轮计划，也可让助手读取上一轮实际结果，诊断问题并提出继续、修改或停止建议。新方案仍需审批。

需要真实模型的部分是 DSH 规划与诊断；示例执行、矩阵调度、统计和证据管理不依赖模型响应。

## 三个 P0 的实现范围

| 方向 | 已实现行为 |
|---|---|
| 项目级 Research Agent | 持久化研究状态及修改历史；状态和工作流摘要注入助手上下文；读取真实资源后通过 MCP 保存计划；助手状态修改先进入待确认提案；计划版本、前序计划关联、固定六步依赖和检查点 |
| 实验自动化 | Python JSON/CSV 适配；方法 × 种子 × 样本预算矩阵；并发队列、有限重试、暂停/取消、进程树终止、崩溃恢复；固定批准的代码/数据哈希、解释器与依赖；命令、Git、种子、时间、指标、日志、退出状态；自动统计及继续/修订/停止建议 |
| 科研证据网络 | SQLite 对象与关系表；论文、假设、实验、结论、数据、代码、决策、报告节点；来源位置、文件 SHA256、时间和状态；支持/反驳/检验/使用/派生等关系；图、表、搜索、来源核查；正式结论区分证据不足、初步支持、人工核查证实和范围内反驳 |

批准后不能直接改计划。代码、数据、环境或已完成产物改变时，续跑和确认会拒绝复用，要求创建修订计划。重启后的工作流处于暂停状态，用户启动续跑后跳过已校验完成单元；中断尝试也计入重试预算。预算耗尽需要重新审批。

未确认的结果不会改写正式科研状态。报告和实验记录可先进入资源库和证据网络供审查，自动结果最多是初步支持或协议范围内反驳，不自动升级成普遍成立的事实。确认过程中的部分写入可重试，不重复发布同一研究决策。

## 接入自己的 Python 实验

把脚本、数据、辅助代码和配置放在项目目录。所有影响结果的输入都应列在 `inputs`；主脚本会自动纳入哈希清单。参数不经过 shell 拼接。

```json
{
  "question": "候选方法是否稳定优于基线？",
  "hypothesis": "候选方法在相同训练预算下提升准确率",
  "python": "C:/path/to/venv/Scripts/python.exe",
  "inputs": ["resources/data.csv", "resources/helper.py"],
  "methods": [
    {"name": "baseline", "script": "resources/run.py", "args": ["--method", "baseline", "--seed", "{seed}", "--budget", "{budget}", "--metrics", "{metrics}"]},
    {"name": "candidate", "script": "resources/run.py", "args": ["--method", "candidate", "--seed", "{seed}", "--budget", "{budget}", "--metrics", "{metrics}"]}
  ],
  "matrix": {"seeds": [11, 22, 33], "budgets": [64, 128]},
  "protocol": {"metric": "accuracy", "direction": "maximize", "baseline": "baseline", "split": "固定种子的分层训练/验证划分；预处理仅拟合训练集", "minSeeds": 3, "minImprovement": 0.01, "maxStd": 0.05},
  "budget": {"maxRuns": 12, "concurrency": 2, "timeoutSeconds": 120, "retries": 1, "wallSeconds": 900}
}
```

脚本向 `{metrics}` 指定的绝对路径写出一份 JSON，例如：

```json
{"accuracy": 0.86, "split_id": "实际训练与验证行索引的稳定哈希"}
```

也支持方法设置 `"format": "csv"`，输出表头加一行结果。主指标须是有限数字；同种子、同预算的不同方法须提供相同的 `split_id`。还可使用 `{output}`（尝试产物目录）、`{project}`（项目根目录）。`direction` 支持 `maximize` 和 `minimize`。

## 判断规则与边界

- 以相同种子和预算配对比较候选方法与基线。检查种子数量、划分一致性、平均收益、收益标准差及最差收益；某方法必须在所有配置预算下达标，才建议继续验证。
- 报告提供均值、标准差、最小/最大值和探索性 bootstrap 区间。它不是独立确认试验，也未做多重比较校正；继续验证建议要求独立留出数据和消融实验。
- `split_id` 是脚本申报的标识，不能证明无数据泄漏。输入哈希证明文件是否改变，不证明科学结论正确。未声明的辅助文件无法自动追踪。
- 示例是合成分类数据，不代表任何真实科研领域的算法优越性。Random Forest、Extra Trees 和 Logistic Regression 都实际训练并输出指标。
- 资源限制是最大单元数、并发、重试次数和时间，未实现 GPU/内存硬配额、远程集群或云端调度。
- 当前是固定算法对照工作流，尚非任意 DAG 编辑器。下一轮由助手建议、用户审批；不无限自动更改目标或消耗算力。
- P1 深度文献引擎、完整自动泄漏审计、P2 多 Agent、云同步及扫描件 OCR 不属于本次 P0 交付。

## 本地存储

SQLite 新增 `research_states`、`research_state_history`、`research_workflows`、`evidence_nodes`、`evidence_edges`；保持现有工作区数据兼容。

- `projects/<id>/experiments/workflows/<workflow>/<run>/attempt-<n>/`：每次尝试的日志、指标、元数据和其他产物。
- `projects/<id>/outputs/workflows/<workflow>/`：报告、汇总、分析及批准协议。
- 备份包含数据库和项目产物；运行期间拒绝备份/恢复，避免截取不一致状态。运行中的项目也不能直接删除。

## 验收记录（2026-11-16）

验证全部使用隔离数据目录，不写入用户项目。

| 验证 | 内容 |
|---|---|
| 真实矩阵两轮 | 每轮 3 方法 × 5 种子 × 3 预算，共 45 单元；暂停后跳过 4 个已完成单元续跑，最终确认状态、记忆、报告和证据；每轮 51 个证据节点、183 条关系 |
| 浏览器完整流程 | Edge/Playwright：状态编辑、计划 JSON 编辑、审批、9 次真实训练、图表、CSV 下载、结果确认、证据来源、刷新持久化 |
| 真实 DSH | 读取项目资源、通过 MCP 保存有效计划草案；未审批不执行，也未提升正式研究状态 |
| 强制崩溃 | 只结束调度主进程，检查实验子进程自行退出；重启恢复暂停，复用成功单元、重跑中断单元 |
| Windows / Linux | 本机 Windows 和 WSL Linux 下验证工作流边界与崩溃恢复 |
| 旧功能回归 | 6 项本地业务测试、并发合并测试；真实 MCP 写入、记忆、备份恢复和迁移后 DSH 会话续接 |

边界回归覆盖：审批及并发版本冲突、批准后改代码、日志/重试、重试耗尽、划分不一致、产物篡改、确认幂等与部分发布恢复、提案不覆盖正式状态、取消、运行期间备份/删除阻止、单次与总超时、跨项目来源隔离、CSV 和非有限指标。

多轮检查中修复了 Windows 子进程日志转发导致的错误分类失准、空证据异常列表误提示、报告阶段完成状态同步、异常路径预算累计、结果部分发布后的重复确认问题。
