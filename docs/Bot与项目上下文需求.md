# Weave Bot 与项目上下文需求

本文记录通用项目工作区的 Bot、共享上下文及验收条件。科研流程是这些机制的一个主要应用。[范式开发说明](../.agents/skills/weave-bot-paradigms/SKILL.md)描述决策、数据和前端约束，[前端参考](../.agents/skills/weave-bot-paradigms/references/paradigms.md)给出范式排布示例。

## 项目与功能 Bot

- 用户与 LLM 通过助手或项目对话共同决定需要哪些范式、每类几个 Bot、要复用哪个现有 Bot。项目从实际项目任务出发，按需添加目标、笔记、思维导图、点子和工程台。
- 每个 Bot 有独立名称、职责、对话和稳定 ID。一个 Bot 对应一个范式及一种由 LLM 根据任务元素决定的主排布。分类树、分组和排序属于当前排布内部。产品页无排布切换入口。
- 创建沿用项目里的原有入口，用五张较大的内置范式插图卡供用户选择，只填名字。弹窗紧凑，五张卡片在窄屏可换行。卡片下方提供「项目扩展范式」。已有 Bot 页面按各自排布在主区呈现，退出旧的通用工作台。
- 项目扩展范式以语义描述写明要展示什么、什么时候记录、如何组织，并定义展示元素和一种排布。定义保存后仅在当前项目内复用。Bot 可以选择该定义并独立命名。项目服务校验扩展归属及记录的自定义元素。对话中可请 LLM 根据语义描述选排布和元素，再保存扩展。
- 聚类把同项目、同范式的小 Bot 组织成一个同范式的大 Bot。用户与 LLM 根据合并后的职责选择一种排布，以大 Bot 作为统一入口。成员、会话、出处和已有成果保持可追溯。跨范式通过任务及成果引用交接，跨项目继续按既有边界隔离。
- 删除时处理该 Bot、未完成任务与定时任务的归属。其他地方仍在引用的资料和结果保留。工程台按项目对话权限使用原生工具运行实验，记录实际环境、参数、日志、指标和产物。

## 助手和项目对话

| 角色 | 职责 | 交付 |
| --- | --- | --- |
| 全局助手 | 识别目标项目，确认转交范围，协调跨项目事项。 | 将用户需求、约束与授权引用交给目标项目主对话。 |
| 项目主对话 | 澄清目标，制定验收标准，拆任务、选 Bot、安排依赖，核对成果并处理冲突或变更。 | 可追溯的分派与项目决定，以及引用各 Bot 证据的项目结论。 |
| 功能 Bot | 作为原生子智能体执行已绑定的任务，发布工作依据和进展，提交可验收成果。Bot 的稳定 ID 关联职责、画布与历史，每次分派关联本次原生子对话。 | 带证据的文字、图表、运行记录或项目文件，并回报完成、阻塞或待继续。 |

- 全局助手只负责管理和协调。具体任务转交已明确的项目主对话，再由该项目安排执行。全局助手完全访问时可直接转交，其余级别由用户在全局对话确认。转交使用目标项目对话的权限。
- 原生子智能体入口在助手和项目主对话顶部均不可见，包括实际产生子智能体记录以后。Weave 的项目任务、工具、对话和 Bot 入口继续可用，已有对话记录可查。

### 执行分派约束

- **看用户要的结果来决定路径。** 查已有结论和状态、讨论方案、选择优先级、确认项目决定和汇总已返回的成果，由项目主对话处理。要求检索并核验新证据、开展分析或实验、生成报告或图表等可独立验收的交付，必须由 Bot 执行。用户明确点名 Bot 时优先走相应的分派或插话入口。直接提问与全局转交适用同一规则。对于含有决策和执行的请求，项目主对话保留决策部分，将执行拆成任务。
- **先登记任务，再执行。** 项目主对话给每项任务指定目标、输入或来源引用、验收标准、前置任务及承接 Bot，绑定项目、发起对话和请求。优先复用职责匹配的 Bot；只有一项可独立验收的工作时可只派一个。互不依赖的任务在现有并发上限内并行；下游等到前置成果已验收并可读取后启动。拆分边界以交付和依赖为依据。缺少合适 Bot 时，按当前权限创建一次性 Bot。
- **由宿主约束操作与结束条件。** 以宿主绑定确认项目主对话和 Bot 身份。项目主对话可使用项目管理、查阅、审批协调和分派能力。执行型工具按职责在已绑定的 Bot 中开放，由宿主核验权限、项目范围和任务状态。执行型请求按请求 ID 核对分派记录；收到 Bot 成果并核实交付后才可作为已完成回复。排队、执行、等待审批、失败和阻塞分别显示实际状态。如果权限不足、无可用 Bot 或运行时无法启动，反馈原因及继续所需的条件。项目主对话的文字回复本身不能作为执行凭证。
- **由项目主对话验收和协调变更。** Bot 返回结果、出处与待核验项，项目主对话按原任务标准核对。需要补证时更新任务并交回 Bot。用户改需求或撤回依据时记录变更，标记受影响任务并决定继续、暂停或重派。最终项目回复汇总结论、分歧和未完成事项，链接实际执行 Bot、画布卡片及交付。

### 科研任务澄清

执行前按任务类型检查会改变结果的缺项。先从本对话、用户已确认的项目规则和引用材料补齐。综合请求逐项判断，每轮集中询问最多三个关键问题。已经明确的条件直接沿用，呈现方式等可逆选择可按合理默认值处理。

| 任务 | 执行前需要明确 |
| --- | --- |
| 文献检索或综述 | 研究问题和纳入范围。系统性筛选需要时再问时段、来源或纳排限制。 |
| 证据核验 | 要核查的主张，以及依据或可查找原始来源的范围。 |
| 数据分析 | 数据来源、要回答的问题或比较对象。比较口径会影响结论时确认指标。 |
| 可视化 | 可用数据和图表要呈现的变量、趋势或对比。 |
| 实验或复现 | 假设或复现目标、必要输入、成功标准。会影响资源消耗时确认试跑或正式运行的边界。 |
| 报告、代码或其他产物 | 用途、处理对象和可辨认的交付结果。 |

条件不足时通过 DSH 原生提问卡接收选项或自由输入，提交后重新判断。跳过必答项、关闭卡片或选择暂停时，当前请求停在已授权范围。项目主对话、直接 Bot 对话及项目转交、显式分派和点名 Bot 适用同一判断。Bot 工作台有「打开提问卡」入口，被分派的子智能体将待确认事项交回项目主对话。

### 科研闭环与推进确认

`research-project-loop` 随 Weave 安装。科研请求由会话入口判断并自动加载闭环指导。项目主对话分派科研任务时，执行 Bot 同时收到整体流程和本范式的职责。先完成用户指定的步骤。研究推进范围尚未确定时，在原对话询问继续、调整或停在哪个阶段。启动实验和超出原授权范围的后续动作仍由用户决定。

笔记交接文献与数据依据，思维导图整理关系，点子形成可验证假设，目标定义验收条件，工程台回传实验结果。已保存记录及修订、撤回、实验状态和指标摘要进入同项目的共享事件流。项目主对话和 Bot 在相关工作中读取变化，核对是否影响既有决定。依赖的前置成果已修订或撤回时，后续任务需要重新核对。相关性不足的活动保持独立。

## 助手与 Bot 插话

项目主对话可通过 `labweave_bot_delegate` 将一次性任务交给现有 Bot。一次调用最多接受三个独立任务，从 DSH 的原生进程内 Spawn 并行执行。子会话按分派绑定项目与 Bot，继承发起会话的权限并根据职责调用工具，使用结构化回执返回原对话。有执行权限时，工程台可执行并更新本 Bot 的实验记录。

- 持续职责重叠的同范式 Bot 可以聚到一个长期 Bot 下。项目侧栏从聚类入口访问成员，查询聚类成果可按成员回查原始记录。范式相同且任务独立时可以分别保留。
- 一次性交付缺少合适 Bot 时，项目主对话可建立临时 Bot。仅在子任务确认完成、成果写入成功且该 Bot 没有长期分工、定时任务、独立对话或聚类归属时自动归档。阻塞、失败和需要后续工作的 Bot 保持活动。项目有归档成员时，侧栏显示与「聊天」同级的「归档 Bot」入口。展开后可查看历史或恢复 Bot。最后一个成员恢复后入口隐藏。

### 项目任务

项目主对话顶部的「项目任务」默认显示项目内的 Bot 分派，按钮数字表示待启动和执行中的任务数。面板按当前 Bot 归属分组，展示状态、任务内容、分派和更新时间，并可展开结果、返回发起对话或查看 Bot。聚类后按新归属呈现，同时标注实际执行的成员。Bot 归档或移除后，其任务记录保留并标记相应状态。服务重启时，遗留的未结束分派标记为已中断。定时任务继续通过面板内的「定时任务」查看。

- 助手和 Bot 都是可加入对话的发言者。用户可以在当前会话直接点名任何有权参与的助手或 Bot。项目主对话可以邀请负责该任务的 Bot 插话，Bot 对话可以邀请助手补充项目背景、协调依赖或确认下一步。全局助手会话明确目标项目后，也可以邀请该项目的 Bot。
- 已参与同一任务的助手或 Bot 可以在有需要用户关注的进展、结果、阻塞或澄清问题时主动插话。项目主对话协调发言顺序，合并重复进度并保留原发言者。正在生成的消息完成后再插入待发消息，避免打断用户输入或覆盖当前回复。
- 插话作为独立消息出现在当前会话的时间线里，显示发言者的名称，关联所回应的消息或任务。用户可以在原会话继续追问。重新打开会话后，历史插话仍按原顺序显示，保留发言者及关联。
- 后台插话回到发起任务时绑定的会话。投递前校验目标会话、发言者和资料引用的项目权限，同一事件重试只显示一次。项目数据的可见范围继续按该会话已授权的项目确定。

## 项目对话流与实时画布

- 功能 Bot 的对话将每次分派的发起消息、工作进展、原生工具状态和交付组织为一个任务组。直接对话沿用 Bot 自身的会话。选择「跟进任务」后，输入发送到发起该任务的项目主对话，并带上原分派引用，由主对话安排新的执行；原运行保留原先的输入与成果。
- 执行 Bot 在每次工作中读取适用的项目决定、本次发起消息、自身分派和明确的前置成果。用户可从任务组返回发起对话，或回查原始交付及后续跟进。

- 将与项目工作有关的原始需求、澄清、已确认决定、任务变更、可公开的工作摘要、进展和成果引用写入同项目的有序事件记录。每条更新关联真实发言者、来源会话和消息，有任务时关联任务、Bot 及执行会话。原文保留在原会话，事件携带必要摘要及可验权的来源引用。用户可查看采用了什么证据、为何选某种方法、哪些结论尚待核验。模型的私有推理和工具凭据不进入同步记录。
- 全部同项目 Bot 共用这条项目事件流。运行中的 Bot 在接单、进入下一工作步骤或采用前置成果前读取新增的相关更新；空闲 Bot 在下次工作时补读，无需为每条消息启动模型。工作中的项目变更带上受影响的任务与依据版本。后端在保存成果和启动依赖任务时校验版本，避免把基于旧要求的结果当成当前成果。
- Bot 画布是该 Bot 任务事件的视图。工作开始时显示目标、状态和可检查的提纲；随着工作推进，按事件更新可审阅的文字草稿、结构化图表、实验进展和文件引用。每张卡片有稳定身份，支持原地更新和查看来源。任务交接使用已验权的成果引用，画布按相应 Bot 的范式和主排布呈现。聚类后的画布标注实际贡献的成员。
- 草稿标为待核验，正式成果在成功保存后显示正式状态。已生成的文件保存在项目的 `outputs` 并可从对应卡片打开。等待确认、失败或待继续时保留有效草稿与阶段成果，标注当前状态。保存失败的交付可重试。
- 打开画布时先显示已有状态，再持续接收新增事件。在任务完成前就能看到已保存的更新；重连或切换页面后从最后读取位置补齐，同一事件重试只更新一次。项目任务与画布使用同一组任务状态，主对话只在关键进展、需要决定或交付时插话。

- 画布可全屏显示或最小化。收起画布后，对话区占满剩余空间，点击 Bot 标题旁的「显示画布」恢复原高度。缩放统一应用于节点、文字和连线，保留画布内部的相对比例。用户可添加根节点，也可从已有内容节点添加分支。删除节点清理关联连线并保留下级节点和原始资料。
- 画布每收到一张新卡片，就动画平移至该卡片位于视口中央，并保持缩放。同一批收到的多张卡片按到达顺序逐张聚焦。收起或拖动画布期间收到新卡片时，等画布恢复或拖动结束后聚焦。已有卡片的文本、图表或状态更新保持当前视角。
- 分支与前置依赖从上游卡片指向下游卡片，使用箭头。普通关联显示无方向的虚线。同一项目、同一聚类内可跨成员连接已保存的卡片，服务校验连接范围并拒绝形成循环的方向关系。工程台的实验运行卡片可作为内容卡片的上级。
- Bot 可在发布阶段草稿时登记本次任务中的草稿关系，或连接本 Bot 和同聚类中已保存的卡片。草稿发布后画布同步显示连线，有关系的草稿在正式成果保存后保留在画布中。正式成果可带已保存卡片的关系，关系以实际分支、前置依赖和关联为依据。
- 多张草稿作为正式交付时，由宿主先为已核对的草稿分配正式记录 ID，再映射连线并校验归属、循环和项目规则。正式卡片与交付状态一起提交。原发起会话有写入权限时可按原分派重试，重复提交返回同一批记录。历史 Bot 对话保留草稿并可打开对应正式成果。
- 画布在 Bot 标题下方以完整的圆角矩形呈现，任务进度显示在「添加节点」所在的工具栏。分派的阶段草稿与最终回复同时进入执行 Bot 的对话记录，可打开对应图表和文件。更新同一张草稿时同步更新对应消息，归档或重新打开页面后可回查。Bot 对话用可折叠的执行过程展示思考状态、工具动作和结果状态，任务来源、跟进和查看记录使用与项目主题一致的操作样式。
- 画布卡片按记录展示标题、摘要、日期、图片或图表预览，并在详情提供来源、链接与文件。详情的配图区域也可展示交互图表，支持按指标查看、切换图表类型以及用指针或键盘检查数据点。一条记录有图表和配图时，默认打开图表，可在同一区域切换。
- Bot 分派与直接对话共用正文约定，首段说明结论，关键发现使用 Markdown 加粗。分派摘要与执行指令分字段保存。卡片和对话以带下划线的名称链接项目资料、原文与产物，项目资料和文件由宿主核验归属后打开。已有消息保留原文，显示时将可识别的旧记录编号和卡键替换为资料引用，保留可识别的 DOI。
- 验收条件说明用户能看到和核对的成果。内部工具名和接口调用要求保存在任务指令中。Bot 对话、卡片和执行过程以用户可读的名称呈现操作，历史消息采用同样的显示规则。
- 工程台的实验卡片约每三秒更新状态、最新指标和缩略图，详情同步更新交互图表。已登记的 CSV 或 TSV 产物有有效数据时，图表读取最近的数据点；也可由实验记录提交结构化指标。聚类画布显示成员各自的实验并保留归属。
- 所有 Bot 画布的卡片概览使用短标题和一两句摘要。点开后呈现可独立阅读的短文，先给出发现或进展，再按需要展开证据、方法、局限和下一步。正式记录和阶段草稿分别保存摘要与正文，已有记录可从正文提取概览。

### 运行时接入

- 固定版本 `0.2.2rc2` 通过宿主工具检查限制项目主对话的执行操作，通过原生回复流校验执行请求的实际分派与返回状态。直接请求由当前模型单独识别意图。已确认的全局转交由宿主识别，并校验指定 Bot。归属明确的分派关联发起消息及已声明的前置任务。
- 项目需求、规则或决策记录、分派状态和阶段成果摘要保存在项目事件流。每个 Bot 在下一原生模型步骤读取增量。宿主验证已声明依赖的完成状态和当前规则版本，规则更新后过期结果留在阶段记录中供复核。撤回的用户消息退出共享读取，并保留撤回事件供已读过该消息的 Bot 核对。
- Bot 通过画布草稿发布文字、图表和 `outputs` 文件引用。内容和运行状态以约 1.5 秒轮询恢复，继续使用 Bot 原来的排布和项目空间存储。实验日志仍通过工程台的原生运行记录读取。
- 当前验证使用固定内核和本机模拟模型，覆盖模型尝试越权执行、伪造完成回复、并行分派及运行中画布。自由文本的意图识别取决于配置的模型。正在进行的单次模型调用在下一步骤同步项目更新。

## 空间存储

- 项目对话的「项目文件变更」按会话显示其运行期间记录到的新增、修改和删除，使用项目目录内的相对路径。分派 Bot 产生的文件变更回到发起会话。记忆、目标和卡片通过各自的项目界面更新，结构化保存回执保持在运行记录中。

- 项目主对话与同项目 Bot 交付的文档、代码、图片和数据等文件统一写入项目自己的 `outputs` 目录，文件格式不限。右侧「工具 → 空间存储」使用正方体图标，将这些生成文件、实验产物和导入文件按日期分组，最新的排在最前。
- 删除会话后交付文件仍可在项目中使用。确认删除整个项目时清理该项目的生成文件，保留导入资料、关联本机来源和代码仓库。

## 共享记忆与主动检索

- 以项目为共享范围。项目主对话与同项目的所有 Bot 读写同一套项目记忆和规则，不因发起会话或 Bot 范式而分库。其他项目不继承这些资料。全局助手维护自己的全局记忆，通过对话明确项目后可回查该项目。
- 主对话确认的新规则、决定或阶段变化进入共享状态。Bot 保存的已核实结果、决定和有用记录也进入共享状态，供主对话或其他 Bot 后续检索并使用。遵循项目主对话的同步约束，在接单和下一执行步骤使用最新的项目状态。
- 助手掌握精简的核心要点。根据当前指令、主题和上下文主动搜索相关记忆全文，检索不限于当前对话、置顶记录或最近摘要。问到既有规则时检索适用规则，问到历史工作时按任务关键词检索。无需为问候或无关操作调取记忆。
- 用户确认的持久项目规则可归入 `rule` 并置顶。规则变更时更新原记录，让同项目对话采用最新版本。资源库和历史对话作为可追溯来源使用，待核查推断保留其状态。

## 验收条件

1. 在助手和项目对话启动过原生子智能体的对话，顶部均没有子智能体入口，其余顶部操作可用。
2. 主对话保存一项项目规则，Bot 在实质任务中主动检索并遵循。Bot 记录已核实结果后，主对话能按指令主动找到。修订同一规则后，下一轮检索使用新版本。
3. 给另一项目或全局助手的普通会话发同样的检索请求，项目专属记忆不会出现在默认结果。明确指定目标项目后，全局助手可以回查目标项目的相关记录。
4. 在同一项目打开两个同范式、排布不同的 Bot。两页各显示一种排布，聚类后仍只有一种主排布，成员记录可追溯。跨范式聚类请求被拒绝。
5. 创建弹窗只有范式选择和名字输入，适配窄屏。目标、笔记、思维导图、点子和工程台的排布依据可回查的数据渲染。
6. 在项目主对话点名 Bot，在 Bot 对话点名助手。两者分别以自己的名字在当前会话发言，用户可以原地追问，重开会话后仍能看到插话。
7. Bot 在项目主对话后台完成任务，助手在 Bot 对话发现需用户确认的依赖。两条主动插话各回到对应对话。切换页面、并发回复或重复投递时，消息仍按序出现且只显示一次。未明确目标项目的全局对话和其他项目对话收不到该项目的插话。
8. 在项目主对话直接请求「对照两篇论文核对数据划分，复跑最小基线并给出带证据的报告」，再从全局助手转交同类请求。两条入口都能在「项目任务」看到实际承接 Bot；原文核对和环境检查可并行，复跑等待协议与环境就绪，报告引用已验收的证据和实验结果。用「上次结论是什么」对照，查阅由项目主对话直接完成。
9. 模拟模型在执行请求中绕过分派，直接运行命令、写报告或仅回复「已完成」。宿主拒绝越过角色边界的操作，项目任务和对话均不显示虚假的完成。分派不可用、缺少权限、取消或任一依赖失败时，能看到实际状态及阻塞原因。
10. 在长任务运行时切换到执行 Bot 的画布，依次看到已保存的工作摘要、文字草稿、基于实际数据的图表及可打开的文件。修改项目要求后，受影响的 Bot 在下一步采用更新，基于旧要求的结果无法使下游启动。刷新或重连后更新有序、无重复；另一项目无法订阅事件或打开产物。
11. 发起缺少推进范围的请求。浏览器在输入处出现原生提问卡。选择暂停时无新分派，提交选项和自由输入后按确认范围分派。首阶段结束时，下一阶段的决策通过新的原生提问卡确认。
