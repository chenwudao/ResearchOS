# LabWeave 项目介绍与功能说明（ResearchOS V2.0 历史版本）

> 历史版本说明：项目现名 LabWeave；本文保留 ResearchOS V2.0 的名称和对应版本记录。

编写日期：2026 年 11 月 16 日

对应版本：ResearchOS V2.0 本地版，代码提交 `3b681a1`

用途：帮助使用者和项目成员理解项目定位、已实现功能、工作流程和当前能力边界。

## 1. 这个项目是在做什么

**ResearchOS 是一个以科研项目为单位、由 AI 助手参与推进工作的本地科研工作区。**

它把科研过程中常见的事情放在同一个项目空间里：与助手讨论问题、追踪论文和新闻、记录研究点子、安排目标、管理论文与代码、运行任务、整理实验结果，以及保存研究过程中的重要决策。

例如，用户研究一个方向时，可以先创建课题、填写背景，再上传论文和导入代码仓库。助手结合这个课题的资料和目标开展分析，将产生的建议写入点子，将后续工作整理成目标，并把执行报告和文件保存到资源库。之后继续研究时，助手可以读取之前的任务结果和项目记忆。

项目要解决的核心问题是：**让资料、想法、计划和执行结果能够在同一课题中相互关联，减少反复整理资料、复制上下文和切换工具的工作。**

这里的 “OS” 表示科研工作区的组织方式；程序本身是一套在本机运行、通过浏览器使用的应用。

## 2. 用户会看到哪些模块

界面有一个全局聊天入口，以及多个独立项目空间。每个项目围绕助手、动态、点子、目标和资源库组织工作。

| 模块 | 用来做什么 | 当前已实现的功能 |
|---|---|---|
| 全局聊天 | 从多个课题的角度安排工作 | 通过自然语言创建项目、查询项目、向指定项目写入内容和建立任务 |
| 项目空间 | 集中管理一个课题 | 创建、切换、重命名和删除项目，填写研究背景，保存项目对话和栏目数据 |
| 项目助手 | 讨论问题并执行科研任务 | 读取项目背景、目标、动态、资源和记忆；调用工具；返回回复、报告和执行产物 |
| 动态 | 跟踪研究方向的新信息 | 按主题获取论文、新闻和公开代码仓库，定时更新，收藏、转点子或隐藏条目 |
| 点子 | 积累并迭代研究想法 | 新增、修改、删除点子，保留论文来源，将点子转为目标，开启每日项目复盘 |
| 目标 | 把想法变成可推进的计划 | 设置截止日期、父目标和子任务、前置依赖及完成状态；展示时间表和关系图；发起执行任务 |
| 资源库 | 集中保存课题材料与成果 | 上传 PDF 和本地文件，导入 Git 仓库，创建实验环境，阅读或下载资源，登记生成的文件 |
| 任务与执行记录 | 了解助手正在做什么 | 查看状态和执行事件，确认执行、批准或拒绝工具操作、回答澄清问题、取消及继续任务 |

普通聊天点击“发送”后会启动 DSH 任务；“交给 DSH 执行”会先建立待确认任务。执行中需要用户答复或授权时，任务面板会显示对应操作。

## 3. 已经增加了哪些科研能力

### 3.1 论文阅读与多论文对比

上传带文字层的 PDF 后，可以在资源库逐页读取内容，并让助手进一步分析论文的研究问题、章节结构、方法、实验和局限。助手通过资源 ID 和页码读取材料，阅读任务要求标明依据和无法读取的部分。

导入至少两篇 PDF 后，可以发起论文对比任务，让助手整理不同论文的研究问题、方法、数据集、指标和局限，并将对比报告保存为项目文件。具体分析质量取决于论文文本是否可读、任务要求和模型实际执行情况。

### 3.2 论文引用关系图

输入论文 DOI 后，系统从 Crossref 查询参考文献，展示引用关系图及参考文献列表；有 DOI 的节点可以跳转到论文。

这项能力展示的是数据源返回的引用关系。目前图中最多展示前 24 条参考文献，下方列表展示本次获取的完整结果，后端每次最多返回 150 条。数据源没有提供参考文献时，界面会说明情况。

### 3.3 科研记忆

科研记忆用于保存研究决策、重要发现、已执行任务的结果等内容。用户可以查看、补充和删除记忆，助手也可以通过工具搜索和写入。

例如，项目决定“先使用某个基线方法”“暂不开展 GPU 训练”“下一步验证某个假设”，这些信息可以保留，供后续任务参考。系统会选取部分近期记忆和任务结果加入上下文，也提供按关键词查询的工具。

### 3.4 实验跟踪

资源库中的“实验跟踪”支持记录实验名称、参数、指标、日志、状态及关联任务，并提供修改、删除和指标对照表。

实验状态包括计划中、运行中、已完成和失败。记录可以由用户填写，也可以由助手调用工具写入。参数和指标以 JSON 对象保存，适合记录学习率、随机种子、样本数量、准确率、耗时等信息。

创建实验环境会在项目目录下建立独立 Python 虚拟环境。具体实验所需的数据、依赖和计算资源仍需按任务准备；实验记录由用户或工具写入，并非自动捕获所有外部程序的运行。

### 3.5 科研任务质量评估

资源库中的“任务质量评估”用于评价已经完成的项目任务，支持人工评分和让 DSH 读取任务证据后评分。

| 评分维度 | 关注的问题 |
|---|---|
| 完整性 | 是否完成了原始任务要求 |
| 正确性 | 结论、计算和操作是否合理 |
| 证据质量 | 是否有资料、日志或产物支持结论 |
| 可复现性 | 是否保留了足够的步骤、参数和结果 |

每项 0–5 分，四项合计换算成百分制。记录必须包含评分依据，并标明评估来源。当前实现的是任务级评分与记录功能，没有预置覆盖各科研领域的标准 benchmark 数据集；模型评分也不等于科学结论已经得到独立验证。

## 4. 各模块怎样配合工作

### 流程一：聊天 → 执行 → 结果保存

1. 用户在项目助手中提出任务，例如分析已导入的代码仓库。
2. 后端读取项目背景、资源、目标和已有记忆，整理任务上下文。
3. DSH 调用模型和工具开展工作，需要时请求用户答复或授权。
4. 页面更新执行状态与事件。
5. 回复保存在会话中，成功任务的结果和生成文件进入相应记录、资源库与项目记忆。

### 流程二：动态 → 点子 → 目标 → 任务

1. 为项目设置关注主题，获取相关论文、新闻或代码仓库。
2. 将感兴趣的动态转为带来源的点子，也可以让助手分析其与项目的关系。
3. 编辑点子，并将其转为研究目标。
4. 为目标设置截止日期、子任务和前置依赖。
5. 从目标发起 DSH 任务，执行文献调研、代码分析等工作。

### 流程三：目标 → 资源 → 实验 → 记忆

1. 为目标准备论文 PDF、代码仓库和本地数据。
2. 创建项目实验环境，让助手检查资料与代码。
3. 根据任务要求运行脚本，保存日志、报告和指标文件。
4. 将参数和结果登记为实验记录，必要时进行任务质量评估。
5. 保存研究决策和下一步计划，后续任务继续使用这些信息。

这些步骤既可以由用户在界面中逐步操作，也可以在明确的任务要求下由助手调用业务工具完成。是否能一次自动完成，取决于资料、环境、授权及执行结果。

## 5. 整个系统是怎样工作的

系统由浏览器界面、Python 业务后端、DSH 执行层、模型 API 和本地存储共同组成。

```text
用户在浏览器中操作 ResearchOS
                │
                ▼
Python 后端：管理项目、资料、点子、目标、任务、实验和记忆
                │
                ▼
DSH：管理原生会话、调用模型、执行工具、处理授权和问答
       │                         │
       ▼                         ▼
DeepSeek 模型 API        ResearchOS 业务工具 / 本机工具
                                 │
                                 ▼
                      SQLite、项目文件、代码和实验环境
```

**ResearchOS 管理科研业务，DSH 负责智能执行。** 助手操作项目时，通过注册的 MCP 业务工具访问同一套后端能力。例如，`idea_create` 保存点子，`goal_create` 创建目标，`paper_read` 读取 PDF，`memory_write` 记录研究决策，`experiment_record` 保存实验信息。

| 技术部分 | 当前实现 |
|---|---|
| 前端 | HTML、CSS、JavaScript，通过浏览器访问 |
| 本地后端 | Python 标准库 HTTP 服务与业务模块 |
| 执行引擎 | DeepSeek Harness 官方 Python SDK，使用完整 `sdk` profile |
| 模型 | DeepSeek API，配置的模型标识为 `deepseek-flash` |
| 业务存储 | SQLite，保存项目、条目、任务、会话关联、记忆等 |
| 文件存储 | 本地项目目录，保存 PDF、代码、实验和产物 |
| 完整执行历史 | DSH 原生会话存储，通过 SDK 恢复 |

每个执行任务使用独立运行进程，取消任务时结束相应进程树。服务重启后，中断任务会标记为失败，用户可以继续原会话；已结束的脚本不会自动从中间某一行接着运行。

## 6. 自动化、保存与恢复

动态订阅默认每 30 分钟检查更新；开启每日复盘后，由 DSH 根据项目情况生成并保存建议。关闭浏览器后，只要本机服务仍在运行，这些后台工作就可以继续。关闭服务后，自动化也会停止。

项目记录保存在本机数据库，上传材料和执行产物保存在本地目录。界面与助手同时修改不同条目时，系统会尝试合并；若双方修改同一字段发生冲突，会保留本机草稿并提示处理。

“备份与恢复”支持创建、下载、导入和恢复 ZIP。备份包括业务数据库、项目文件、Git 元数据和 DSH 会话，恢复前自动生成回滚备份。备份不包含密钥、虚拟环境和依赖缓存，因此换电脑恢复后，需要重新配置 API 和实验环境。

## 7. 已验证到什么程度

2026 年 11 月 12 日的实现与验收记录包含以下验证。本说明整理这些已有结果，没有把编写文档视为重新执行全部测试。

| 验证类型 | 覆盖内容 |
|---|---|
| 本地业务测试 | 数据迁移、依赖约束、项目记忆隔离、实验增删改、版本冲突和恢复 |
| 真实模型集成 | 任务执行、原生历史恢复、取消、工具审批、澄清问答和业务工具写入 |
| 全局助手 | 实际创建新项目，并向正确的项目写入点子 |
| 浏览器流程 | 建立项目、执行任务、点子转目标、资源阅读、实验记录、评分、刷新及并发编辑 |
| 跨平台运行 | Windows 与 Linux/WSL 使用固定依赖完成相关集成测试 |
| 备份迁移 | 恢复数据和文件，将备份迁移到另一目录后继续原生会话 |

还运行过一个实际材料驱动的案例：导入 Transformer、LoRA 论文 PDF 和 LoRA 官方代码仓库，读取指定论文页及源码，运行 Python 参数量计算，保存报告和指标，再登记实验、点子、目标及记忆，最后恢复会话并进行任务评估。

该案例计算了 `d=512、r=8` 时完整方阵的参数量 `262144` 与低秩因子的参数量 `8192`，比值为 `32`。它验证了资料、代码、执行和记录之间的连接，属于参数量核算实验，不代表完成模型训练或论文效果复现。

## 8. 当前能力边界

| 项目 | 当前情况 |
|---|---|
| 云端同步 | 未实现。换电脑需要手动备份、导入，不会自动同步项目 |
| 扫描件 OCR | 未内置。PDF 阅读依赖文字提取，纯图片扫描页需要另外识别文字 |
| 离线使用 | 本地数据可以保存和查看；模型调用及外部资料检索需要联网 |
| 引用数据完整性 | 取决于 Crossref 返回的数据，不能保证每篇论文都有完整参考文献 |
| 复杂实验 | 执行依赖本机环境、数据、硬件和任务要求，不能保证任意仓库一键复现 |
| 任务进度展示 | 约 1.5 秒轮询执行信息，面板保留最近 150 个事件；完整原生历史由 DSH 保存 |
| 质量评估 | 保存人工或助手给出的评分和依据，仍需结合具体研究进行核查 |

当前适合用来组织本地科研项目、辅助文献与代码分析、执行明确任务并积累过程记录。持续使用中的新问题仍需根据实际任务修正。

## 9. 怎样开始使用

在仓库根目录使用 Python 3.12 启动，已验证的具体版本为 3.12.6。首次启动会准备虚拟环境并安装固定依赖。

```powershell
python scripts/start.py
```

然后打开：<http://127.0.0.1:8765>。模型调用需要配置 `DEEPSEEK_API_KEY`，或使用本地密钥文件；已有配置无需重复填写。

建议第一次体验时，创建一个课题、填写背景、上传一篇可提取文字的 PDF，再让项目助手分析这篇论文。随后将建议保存为点子、转为目标，并查看任务记录和资源产物。这样可以直接看到各模块如何配合。

项目的启动、配置和测试命令见仓库 `README.md`；更详细的功能验收与已知边界见 `docs/dsh-runtime-validation.md`。
