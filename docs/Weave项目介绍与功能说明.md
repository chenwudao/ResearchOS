# Weave 项目介绍与功能说明

Weave 是一个开源、本地优先的科研工作区。研究者可以在同一个项目中与助手讨论问题、追踪论文和代码、记录点子、安排目标、执行实验并保存研究决策。项目资料、对话和成果保存在本机，后续任务可以继续使用已积累的材料与记忆。

## 启动与首次使用

在仓库根目录启动。Windows 运行 `.\start.ps1`，Linux 运行 `bash start.sh`。首次安装需要 Python 3.12 和网络。启动器会打开已登录的浏览器窗口。如需自行打开浏览器，启动时添加 `--no-open`，使用终端显示的当次登录链接。默认网页端口为 8770。

首次进入时，在「配置模型 API」中选择供应商并填写 API Key。也可以稍后在「模型与 API」中配置。已有可用配置会随启动恢复。启动参数、运行环境与验证命令见 [README](../README.md)。

## 全局助手与科研项目

顶部「新建会话」打开独立的全局对话。全局助手可以查询多个项目，或为明确指定的项目发起工作。点击助手头像打开活动、审核、人设和记忆面板，可以编辑名称及头像。在「设置 → 助手设置」可管理全局助手使用的模型和权限。

从侧栏选择「新建工作区项目」后，先进入该项目的原生空白聊天。已有项目会保留其栏目。

| 功能 | 用途 |
| --- | --- |
| 聊天 | 在当前项目中提问、发起分析或实验，继续该项目的历史会话。项目助手可使用项目背景、资料、目标和证据。 |
| 动态 | 按主题订阅论文、新闻和公开代码仓库，收藏条目、隐藏条目或转为带来源的点子。 |
| 点子 | 新增、编辑或删除研究想法，保留资料来源，并将选定点子转为目标。开启每日复盘后，助手可生成并保存建议。 |
| 目标 | 设置截止日期、子任务、前置依赖和完成状态，查看时间表及依赖关系。可从目标发起任务，在「实验与证据」中查看进度、审批或答复澄清问题。 |
| 资源库 | 导入本地文件、PDF 及 HTTPS Git 仓库，阅读论文、比较多篇论文、查询 DOI 引用关系，创建实验环境并查看实验跟踪与评分。 |

项目名称及各项功能的显示名称都可以修改。功能可以从侧栏、功能页标题栏或通用设置中改名，也可以请助手改名。功能在改名后继续使用原有标识和记录。项目内的操作限于本项目。

在项目名称旁点击「＋」可以添加功能 Bot，为它指定名称、头像、备注和关键词。也可以在对话里请助手创建。点击 Bot 右上角「工作台」，可以查看任务投递与分工、打开运行日志和图表，或进入原生浏览器与项目代码沙盒。两个项目中的同名 Bot 各自有独立的分工和实验记录。

项目行的齿轮可关联本机来源文件夹。文件留在原路径，项目对话通过只读工具查阅。点击项目「聊天」可打开空白草稿，点击历史条目可返回原会话。

## 从资料到实验

1. **收集资料。** 为项目填写研究背景，在「动态」订阅关注主题，并把论文 PDF 或代码仓库导入资源库。可以让助手阅读指定 PDF 页码，或比较多篇论文的研究问题、方法、数据集、指标和局限。
2. **形成计划。** 将一条动态转为点子，保留它的来源，再把选定点子转为目标。添加截止日期、子任务和依赖后，可以从目标发起文献调研、代码分析或实验。
3. **执行实验。** 在项目聊天的「工具 → 项目代码沙盒」创建或选择 Python 环境。试跑可单次批准，也可按项目授权试跑时长。正式对照实验按计划和预算审批。Bot 工作台也能跳转到对应实验。
4. **整理证据。** 在资源库记录参数、指标、日志、状态和关联任务，通过对照表比较多次实验。已完成的任务可按完整性、正确性、证据质量和可复现性评估，记录评分依据及人工或助手来源。
5. **留下研究决策。** 核查正式实验报告后，确认的研究决定会保存在项目科研状态和业务数据库中。跨项目的研究偏好可另存到全局助手的记忆。

论文引用图使用 Crossref 返回的参考文献，带 DOI 的节点可跳转到相应论文。实验资源、参数、报告和产物可在项目内与假设、证据和结论关联。用户可在目标的「实验与证据」中查看相关工作并处理待确认操作。

## 自动化与项目插件

自动化任务可以选择全局助手，也可以显式指定科研项目。项目助手可以安排本项目的任务。动态订阅默认每 30 分钟检查更新，开启每日复盘后，助手按项目情况生成研究建议。浏览器关闭后，只要本机服务仍在运行，后台任务就能继续。

通过「更多 → 创建项目插件」可保存一段可复用的科研指令，并选择单个项目或全部项目可见。点击插件会将指令放入当前项目的聊天草稿，由用户发送。项目聊天和项目任务均按各自的作用域访问数据。

## 本地数据与恢复

业务数据保存在 `demo/.local`，其中 SQLite 保存项目和业务记录，项目目录保存资料、代码及实验产物。会话和网页设置保存在本机用户状态目录，并按科研数据目录区分。运行时在本机管理会话、调用模型和工具，业务服务负责项目数据和科研操作。

退出工作区并停止服务后，使用原启动脚本加 `--backup`，在 `demo/backups` 生成 ZIP。备份包括业务数据库、项目文件、Git 元数据、会话和自动化记录。使用同一脚本加 `--restore 备份文件名.zip` 可以恢复，启动器会先生成回滚备份。会话引用绝对工作目录，包含会话的备份须恢复到原数据目录。密钥、虚拟环境与依赖缓存需要在目标环境单独准备。

## 使用边界与验证

| 能力 | 当前边界 |
| --- | --- |
| 本地使用 | 本地数据可以保存和查看，模型调用和外部检索需要网络。服务关闭后，后台自动化随之停止。跨设备迁移依靠备份与恢复。 |
| PDF 和引用关系 | 逐页阅读依赖可提取的 PDF 文字。扫描件需先完成文字识别。引用图的覆盖范围取决于 Crossref 提供的参考文献。 |
| 实验执行 | 运行依赖项目环境、数据、硬件、批准的预算和具体任务。服务重启后，中断的任务标记为失败，可回到原会话继续安排工作。 |
| 结果评估 | 评分提供任务层面的记录和依据，科学结论仍需研究者核查。 |

早期验收曾导入 Transformer 和 LoRA 论文及 LoRA 官方代码，读取论文与源码，计算低秩分解的参数量，保存报告和指标，并验证实验记录、科研记忆及会话恢复。该案例用于验证材料、代码、执行和记录之间的衔接，实验范围是参数量核算。当前工作区的离线回归和集成测试入口见 [README 的验证章节](../README.md#验证)。
