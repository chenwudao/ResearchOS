# Weave 科研 Bot 与项目上下文需求

本文记录产品需求及验收条件。[范式技能](../.agents/skills/weave-bot-paradigms/SKILL.md)说明实现时如何处理决策、数据和前端。[前端参考](../.agents/skills/weave-bot-paradigms/references/paradigms.md)收录五个范式的十个示例。

## 项目与 Bot 单元

- 用户与 LLM 通过助理或项目对话共同决定需要哪些范式、每类几个 Bot、要复用哪个现有单元。项目从实际研究任务出发，按需添加目标、笔记、思维导图、点子和工程台。
- 每个 Bot 有独立名称、职责、会话和稳定 ID。一个 Bot 对应一个范式及一种由 LLM 根据任务元素决定的主排布。分类树、分组和排序属于当前排布内部。产品页无排布切换入口。
- 创建沿用项目里的原有入口，用五张较大的内置范式插图卡供用户选择，只填名字。弹窗紧凑，五张卡片在窄屏可换行。卡片下方提供「项目扩展范式」。已有 Bot 页面按各自排布在主区呈现，退出旧的通用工作台。
- 项目扩展范式以语义描述写明要展示什么、什么时候记录、如何组织，并定义展示元素和一种排布。定义保存后仅在当前项目内复用。Bot 可以选择该定义并独立命名。项目服务校验扩展归属及记录的自定义元素。对话中可请 LLM 根据语义描述选排布和元素，再保存扩展。
- 聚类把同项目、同范式的小 Bot 组织成一个同范式的大 Bot。用户与 LLM 根据合并后的职责选择一种排布，以大 Bot 作为统一入口。成员、会话、出处和已有成果保持可追溯。跨范式通过任务及成果引用交接，跨项目继续按既有边界隔离。
- 删除处理单元、未完成任务与定时计划的归属。其他地方仍在引用的资料和结果保留。工程台按项目会话权限使用原生工具运行实验，记录实际环境、参数、日志、指标和产物。

## 助理和项目对话

- 助理对应 Weave Manager，明确目标项目后协调工作。项目主对话对应 Project Leader，向项目内各 Worker 分配职责，同步行动依据并接收反馈。LLM Boss 提供底层推理和决策。执行使用 Weave 现有内核和权限边界。
- 全局助手只负责管理和协调。具体任务转交已明确的项目主会话，再由该项目安排执行。全局助手完全访问时可直接转交，其余级别由用户在全局对话确认。转交使用目标项目会话的权限。
- 原生子智能体入口在助理和项目主对话顶部均不可见，包括实际产生子智能体记录以后。Weave 的项目任务、工具、对话和 Bot 入口继续可用，已有会话记录可查。

## 助手与 Bot 插话

项目主对话可通过 `labweave_bot_delegate` 将一次性任务交给现有 Bot。一次调用最多接受三个独立任务，从 DSH 的原生进程内 Spawn 并行执行。子会话按分派绑定项目与 Bot，继承发起会话的权限并根据职责调用工具，使用结构化回执返回原对话。有执行权限时，工程台可执行并更新本 Bot 的实验记录。

- 项目主对话默认分派用户点名的工作和能按职责独立验收的专业任务。同项目 Bot 可检索同一套项目规则和记忆。优先复用已有 Bot，有前置依赖时先完成前置任务。简短查询由主对话直接处理。
- 持续职责重叠的同范式 Bot 可以聚到一个长期 Bot 下。项目侧栏从聚类入口访问成员，查询聚类成果可按成员回查原始记录。范式相同且任务独立时可以分别保留。
- 一次性交付缺少合适 Bot 时，Leader 可建立临时 Bot。仅在子任务确认完成、成果写入成功且该 Bot 没有长期分工、定时任务、独立会话或聚类归属时自动归档。阻塞、失败和需要后续工作的 Bot 仍保留在活动侧栏。已归档 Bot 可从侧栏查看与恢复。

### 项目任务

项目主对话顶部的「项目任务」默认显示项目内的 Bot 分派，按钮数字表示待启动和执行中的任务数。面板按当前 Bot 归属分组，展示状态、任务内容、分派和更新时间，并可展开结果、返回发起对话或查看 Bot。聚类后按新归属呈现，同时标注实际执行的成员。Bot 归档或移除后，其任务记录保留并标记相应状态。服务重启时，遗留的未结束分派标记为已中断。定时任务继续通过面板内的「定时任务」查看。

- 助手和 Bot 都是可加入对话的发言者。用户可以在当前会话直接点名任何有权参与的助手或 Bot。项目主对话可以邀请负责该任务的 Bot 插话，Bot 对话可以邀请助手补充项目背景、协调依赖或确认下一步。全局助手会话明确目标项目后，也可以邀请该项目的 Bot。
- 已参与同一任务的助手或 Bot 可以在有需要用户关注的进展、结果、阻塞或澄清问题时主动插话。Project Leader 协调发言顺序，合并重复进度并保留原发言者。正在生成的消息完成后再插入待发消息，避免打断用户输入或覆盖当前回复。
- 插话作为独立消息出现在当前会话的时间线里，显示发言者的名称，关联所回应的消息或任务。用户可以在原会话继续追问。重新打开会话后，历史插话仍按原顺序显示，保留发言者及关联。
- 后台插话回到发起任务时绑定的会话。投递前校验目标会话、发言者和资料引用的项目权限，同一事件重试只显示一次。项目数据的可见范围继续按该会话已授权的项目确定。

## 实时画布与手动分支

- 分派开始后，所属 Bot 画布显示任务进度。Worker 先发布可查看的提纲，再按批次发布或更新草稿。草稿显示为待核验，任务待继续时保留草稿和阶段交付。正式成果按既有归档流程保存。聚类后的画布保留草稿所属成员的名称。
- 画布可全屏显示。缩放统一应用于节点、文字和连线，保留画布内部的相对比例。用户可添加根节点，也可从已有内容节点添加分支。删除节点清理关联连线并保留下级节点和原始资料。

## 空间存储

- 项目主对话与同项目 Bot 交付的文档、代码、图片和数据等文件统一写入项目自己的 `outputs` 目录，文件格式不限。右侧「工具 → 空间存储」使用正方体图标，将这些生成文件、实验产物和导入文件按日期分组，最新的排在最前。
- 删除会话后交付文件仍可在项目中使用。确认删除整个项目时清理该项目的生成文件，保留导入资料、关联本机来源和代码仓库。

## 共享记忆与主动检索

- 以项目为共享范围。项目主对话与同项目的所有 Bot 读写同一套项目记忆和规则，不因发起会话或 Bot 范式而分库。其他项目不继承这些资料。全局助手维护自己的全局记忆，通过对话明确项目后可回查该项目。
- 主对话确认的新规则、决定或阶段变化进入共享状态。Bot 保存的已核实结果、决定和有用记录也进入共享状态，供主对话或其他 Bot 后续检索并使用。遵循 Project Leader 的同步约束，在接单和下一执行步骤使用最新的项目状态。
- 助理掌握精简的核心要点。根据当前指令、主题和上下文主动搜索相关记忆全文，检索不限于当前会话、置顶记录或最近摘要。问到既有规则时检索适用规则，问到历史工作时按任务关键词检索。无需为问候或无关操作调取记忆。
- 用户确认的持久项目规则可归入 `rule` 并置顶。规则变更时更新原记录，让同项目会话采用最新版本。项目资料和历史对话作为可追溯来源使用，待核查推断保留其状态。

## 验收条件

1. 在助理和项目对话启动过原生子智能体的会话，顶部均没有子智能体入口，其余顶部操作可用。
2. 主对话保存一项项目规则，Bot 在实质任务中主动检索并遵循。Bot 记录已核实结果后，主对话能按指令主动找到。修订同一规则后，下一轮检索使用新版本。
3. 给另一项目或全局助手的普通会话发同样的检索请求，项目专属记忆不会出现在默认结果。明确指定目标项目后，全局助手可以回查目标项目的相关记录。
4. 在同一项目打开两个同范式、排布不同的 Bot。两页各显示一种排布，聚类后仍只有一种主排布，成员记录可追溯。跨范式聚类请求被拒绝。
5. 创建弹窗只有范式选择和名字输入，适配窄屏。目标、笔记、思维导图、点子和工程台的排布依据可回查的数据渲染。
6. 在项目主对话点名 Bot，在 Bot 对话点名助手。两者分别以自己的名字在当前会话发言，用户可以原地追问，重开会话后仍能看到插话。
7. Bot 在项目主对话后台完成任务，助手在 Bot 对话发现需用户确认的依赖。两条主动插话各回到对应会话。切换页面、并发回复或重复投递时，消息仍按序出现且只显示一次。未明确目标项目的全局会话和其他项目会话收不到该项目的插话。
