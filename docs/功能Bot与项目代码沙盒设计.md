# 功能 Bot 与项目代码沙盒

桌面端已接入项目代码沙盒。对话中的 `labweave_sandbox_run` 提交短时 Python 试跑，`labweave_sandbox_status` 读取真实进程和输出，`labweave_workflow_draft` 提交正式对照计划，`labweave_sandbox_run_approved` 可启动已经批准的正式计划。右侧沙盒位于项目主聊天的「工具」中。功能 Bot 的右栏展示对话分配的任务，分配内容以 Markdown 编译视图呈现，职责可直接在右栏编辑并同步给项目，运行记录可回到对应项目聊天查看。

## 当前执行器

- Windows 使用 WSL2，Linux 直接使用 bubblewrap。默认启用新的用户、PID 和网络命名空间，清空宿主环境变量，挂载系统运行库、只读项目和选中 venv，仅开放本次输出目录和私有临时目录供代码写入。缺少执行器、环境或系统无法建立隔离时，面板会显示原因并支持重新提交。
- 项目的 `default` 环境首次使用时创建。也可从面板创建具名环境；兼容的项目目录 `.venv` 和 `experiments/.venv` 分别以 `project`、`experiments` 出现。Windows 的原生 venv 与 WSL 解释器不是同一运行平台。每个托管环境的物理路径可从项目环境接口取得。需要科学计算依赖时，应在对应 Linux 环境中安装所需版本。
- 小试跑每项可申请 1–60 秒。项目可预先授权额度，提交自动预留，完成后归还未用秒数。预算不足时直接进入该项目的待审批队列，可以单独批准这一项。正式矩阵使用自己的批准协议和检查点。服务中断会保留记录。
- 进程标准输出和错误输出分别限量保存，可在面板打开已登记的产物。短试跑的退出码与输出供 Bot 观察，正式结论继续由研究者核查。测试入口为 `tests/test_project_sandbox.py` 和 `tests/integration_project_sandbox.py`，后者使用本机已配置的 DeepSeek 对临时项目发起真实实验。

## 一个项目，两种工作

每个功能插件都是一个能持续记录、归类和回查的 Bot。用户在同一项目底部的对话中交代事情，切换 Bot 会改变默认整理对象和右栏分类，同一场对话与草稿可以接着用。全局 meave 可以把明确指向某个项目的任务交给相应 Bot。

| 功能 Bot | 它维护的记录 | 一次有意义的更新 |
| --- | --- | --- |
| 点子 | 假设、来源、待验证的问题 | 将“先核对候选集合”记为待验证点子，后续实验补到原记录的证据中 |
| 动态 | 对项目有意义的变化 | 两次采集看见同一篇论文时合并出处，有新变化再追加动态 |
| 目标 | 验收条件、进度、阻碍 | 对照一次运行的实际产物，提出完成或继续验证的建议 |
| 资源库 | 文件、仓库、网页、运行产物的索引 | 收录报告并链接到生成它的运行记录，用户可从报告追溯代码与环境 |

Bot 可以用搜索、检测、检查等单位插件。记录使用稳定的项目 ID、Bot ID 和记录 ID，并保留来源会话、消息、文件页码或运行 ID。重复投递同一个来源事件只更新一次。模型可以提出分类、合并和后续动作，已确认的科研结论沿用现有人工确认机制。各 Bot 可共享 DSH 模型会话和运行时，项目数据库承载跨对话的记录。

## Bot 工作台与项目代码沙盒

Bot 页面右上角的「工作台」打开右侧弹窗。顶部显示 Bot 在当前项目里的备注与关键词。「任务」显示原生定时任务的下次投递与投递历史，职责的 Markdown 原文继续保存在 SQLite。「实验」按项目与功能 ID 读取试跑和正式计划。图片可以直接预览，小型 CSV 或 TSV 的数值列按表格行序绘图。较早的正式计划若缺少 Bot 来源，仍可在项目沙盒中查看。

「工具」可以打开 Bot 原生会话的浏览器或项目代码沙盒，也可以从所选实验直接跳转到对应详情。运行预算、计划审批和结果确认仍由项目代码沙盒管理。切换页面时后台进程继续运行。

例如用户说“用本项目的 repro-cpu 运行 check_candidates.py，让点子 Bot 把差异记在这个想法下”。助手绑定目标项目、环境、脚本与来源记录。启动后返回运行 ID，结束时在发起对话中说明结果，原点子能反查本次运行的证据。项目尚无可用环境时，用户可通过对话登记或创建 venv 后继续。

- **启动前**显示项目、脚本、参数、发起 Bot 和环境选择器。环境只列出该项目登记的 venv，并显示 Python 版本、可用状态和最近使用项。用户可在聊天中指定环境，同一项目允许多个环境。
- **执行中**显示运行状态、开始时间、实际环境和逐步追加的标准输出与错误输出。可停止选中的运行及其子进程。同一时间可查看多个运行，切换下次启动使用的 venv 不会改变正在执行的进程。
- **结束后**保留退出码、用时、失败原因与产物。打开产物沿用共用主区。Bot 依据日志或产物更新项目记录，附上可打开的来源。取消和失败也可以形成诊断记录，成功产物须由执行器实际核验。

## 环境与隔离的边界

要使用已有分析依赖，也可把对应平台的环境放在项目内 \`.venvs/<名称>\` 或 \`experiments/environments/<名称>\`。环境选择器显示其相对目录和 Python 版本。托管环境首次创建只含标准库，准备外部依赖在运行前完成；选定环境的 Linux 路径位于“管理环境与试跑预算”中。每次运行会将已选环境以只读方式挂载到 \`/env\`。

仓库根目录的 `.venv` 运行 Leaweave 服务。项目沙盒只使用显式绑定给该项目的 Python 环境。现有 `experiments/.venv` 可以登记为该项目的第一个环境。每个环境有稳定的 `environmentId`、显示名、解释器调用路径、Python 版本和适用的执行后端。Linux venv 常用符号链接指向系统 Python，应保留通过 venv 入口启动的路径。启动时重新核验环境归属、版本和可用性。

venv 负责 Python 解释器与依赖。执行后端负责操作系统层的隔离。每次运行用宿主核验过的项目和会话确定权限，显式传入命令参数及最小必要环境变量。工作目录、可读输入、可写运行目录、临时目录、网络策略以及运行预算都由执行后端落实。服务的模型密钥和业务连接凭据只留在宿主。

DSH 固定版本的 `workspace-write` 是文件写入策略。Windows ACL 后端报告部分强制执行，网络及完整的跨项目读取隔离需要其他机制。界面应从执行器读取实际生效的隔离能力。当任务要求“仅可读取本项目、仅写运行目录或禁网”时，由满足这些条件的容器、虚拟机或等效后端运行；能力不足则保留待运行请求，并显示具体原因。容器中的 venv 必须与容器的系统和 Python 兼容。[DSH 进程沙盒约定](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.2-rc.2/packages/sandbox/sandbox/README.zh.md) · [Python venv](https://docs.python.org/3.12/library/venv.html)

## 宿主与执行器约定

| 操作 | 输入与归属 | 返回或写入 |
| --- | --- | --- |
| 列出环境 | 已绑定的工作区或已授权的目标项目 | 环境 ID、显示名、版本、可用性、隔离后端 |
| 启动运行 | 项目内脚本、参数数组、环境 ID、请求 ID、发起会话和 Bot。关联实验沿用原有计划和预算审批 | 稳定的运行 ID、实际解释器、脚本标识和环境快照。相同请求重试返回原运行 |
| 查看运行 | 服务端核验项目归属的运行 ID，可带日志游标 | 状态、增量日志、实际耗时、退出码、核验过的产物 |
| 停止运行 | 同一授权边界内的运行 ID | 请求停止、等待进程树退出、记录最终状态。已结束的运行保留原结果 |
| 整理结果 | 运行结束事件、项目和订阅它的 Bot | 按运行 ID 与用途去重的记录，保留日志或产物位置，更新回原对话 |

运行记录经历“排队 → 运行中 → 已完成 / 失败 / 已停止”。宿主失联后依据执行器凭据重新确认进程，无法确认或已经消失则记为“已中断”。使用运行 ID 追踪生命周期，PID 仅作为本次运行的诊断信息。重试产生一条关联的新运行，由已经批准的重试预算约束。

## 已有接入点与验收

- [项目试跑队列](../demo/api/project_sandbox.py) 管理额度、请求幂等、会话来源和持久记录。[环境与执行器](../demo/api/sandbox_worker.py) 在 Linux 执行世界中解析项目 venv。
- [实验计划与审批](../demo/api/research_workflows.py) 为原生 Web 新计划绑定环境 ID。旧版已批准计划可在面板创建沙盒修订后重新审批，原记录保存在研究数据库中供追溯。
- [实验矩阵执行器](../demo/api/experiment_runner.py) 与试跑共用[受限进程通道](../demo/api/sandbox_runtime.py)。项目视图从已核验的项目运行记录汇总，使用申请会话、稳定运行 ID 与产物路径定位结果。

验收用两个临时项目。甲有两个 venv，分别启动同一个脚本，检查真实运行报告的解释器与所选环境一致。运行时切换 Bot、右侧页签或下次使用的环境，原任务继续使用启动时的环境。停止一项任务后，另一项继续。乙的会话不能列出、读日志或停止甲的运行。环境缺失或后端达不到所选隔离策略时不启动；重复接收完成事件只产生一次 Bot 归档，归档能打开准确的来源。Windows 与 Linux 分别核验实际支持的隔离策略。
