# 固定五个项目 Worker

2026-11-20 的用户要求替代旧版按需创建与临时 Bot 自动归档策略。

## 原因与改动

旧版本允许模型调用创建、删除、扩展范式与聚类工具，并在临时 Bot 的交付结果保存后尝试自动归档。归档会从活动侧栏收起，表现为工作完成后 Bot 消失。

现在每个项目都提供目标、笔记、思维导图、点子和工程台，各一个。其 ID、名称、职责和主视图固定。服务端目录根据稳定定义生成，记录和会话依旧按项目和 Worker ID 持久化，页面刷新、服务重启或历史归档标记都不能移除五个入口。

| 角色 | 主视图 | 职责 |
| --- | --- | --- |
| A 目标 | 待办清单 | 备忘、优先级、截止日期、完成条件与进度 |
| B 笔记 | 分类资料库 | 来源、摘录、分类、记录更新 |
| C 思维导图 | 关系图 | 文献关系、历史脉络、范式与出处 |
| D 点子 | 探索分支 | 依据记忆与进度迭代操作建议、假设与最小验证 |
| E 工程台 | 工程流程 | 按要求编写代码、运行实验、保存日志指标与可视化产物 |

模型仍可更新内容、建立条目关联、分派任务和更新进度。删除内容条目不等于删除 Worker。任务完成、失败或取消不再触发 Worker 自动归档。

模型工具目录移除了创建、删除及扩展范式工具，宿主移除了聚类工具；旧创建调用幂等返回对应角色，不能新增实例。服务端拒绝结构删除、改名、改职责、聚类与扩展范式，即使绕过界面也不能改变固定目录。删除请求在宿主清理定时任务之前即被拒绝。

## 旧项目兼容

目标、资料库和点子沿用原 ID，展示名称统一为目标、笔记和点子。思维导图与工程台采用稳定 ID。旧自定义 Bot、动态和其他额外入口保留原始记录、来源、布局及会话，放入「历史 Bot」折叠区域，不自动删数据，不强制合并旧记录。

新规则通过目录投影兼容旧数据库，不改写原记录或删除旧会话。恢复旧备份后也采用相同五角色策略。历史 Bot 不作为新的 Leader 自动分派目标，但既有内容可继续查看。

## 验证入口

- `tests/test_fixed_workers.py`：五角色顺序/布局、稳定 ID、重复及并发创建、项目隔离、结构操作阻止、交付保留、旧删除和归档标记、历史资料、工具和上下文约束、内容增删改。
- `tests/integration_fixed_workers.py`：启动隔离的真实原生 Web，检查五种页面、历史资料、宿主删除拦截、刷新及 125% 缩放和 900×720 窗口。
- `tests/test_bot_delegation.cjs`：实际宿主分派逻辑的完成回报保留 Worker，不调用自动归档。
- 保留项目隔离、基础业务、任务分派及全局转交回归。

本次没有重新设计五类画布；沿用既有范式组件并固定默认主视图。实时内容仍由实际用户操作、任务结果和助手读取共享上下文后更新，不伪造后台持续研究。

验收结果：Python 全套 84 项中 82 项通过、2 项按已有条件跳过；8 项宿主 JavaScript 测试通过；真实浏览器五页面、历史入口、删除拦截、刷新、125% 缩放和 900×720 窗口验收通过。
