# 开发基线与接口地图

当前客户端基于固定版 DSH 原生 Web。业务层沿用既有 SQLite、研究工作流和证据数据。迁移及兼容验证见 [DSH 前端适配路线](DSH前端适配路线.md)。

## 目录与职责

| 位置 | 基线职责 |
| --- | --- |
| `start.ps1`、`start.sh`、`scripts/start.py`、`scripts/native_launcher.py` | 准备 Python 3.12 环境，安装固定依赖，启动和关闭本机业务服务与 DSH Web。 |
| `plugins/dsh-labweave-workspace/client/`、`host/` | 通过 DSH 插槽扩展界面。宿主负责认证后的接口、会话归属校验和科研工具注册。 |
| `demo/api/native_web.py` | 接收来自本机插件宿主的请求，核验绑定，并分发业务操作。 |
| `demo/api/features.py`、`bot_activity.py`、`project_sources.py` | 管理 Bot 及其分工、实验列表与预览，以及项目只读来源。 |
| `demo/api/workspace.py`、`project_store.py`、`project_service.py` | 工作区状态、SQLite 中的项目结构及项目业务操作。 |
| `demo/api/tasks.py`、`dsh_worker.py`、`research_mcp.py` | 任务管理、DSH SDK 会话与事件、通过 stdio 提供项目 MCP 工具。 |
| `demo/api/automation.py`、`backup.py` | 后台动态和复盘任务、备份与恢复。 |
| `demo/api/research_api.py`、`research_ledger.py`、`research_workflows.py` | 科研状态、证据、实验工作流和人工确认。 |
| `demo/api/experiment_runner.py`、`experiment_worker.py`、`experiment_analysis.py` | 矩阵实验执行、子进程运行和结果分析。 |
| `skills/`、`examples/` | 现有科研技能说明和算法对照示例。 |
| `tests/`、`docs/` | 离线及集成测试、使用与验收文档。 |

## HTTP 接口

浏览器经 DSH 的已认证连接访问 `/api/labweave/`。常用入口包括工作区列表 `catalog`，按当前会话核验归属的 `project`，及按已登记工作区访问设置和功能页的 `workspace-page`。助手资料、模型配置和消息撤回使用各自的入口。

项目操作使用 `action` 和 `args`。项目设置和只读文件入口见 `settings/*`、`sources/*`。Bot 任务读写通过 `bot_assignments`、`bot_assignment_write` 和 `bot_schedule_*`。实验状态与产物通过 `sandbox/*`、`research/*`、`bot/experiments`、`bot/experiment` 和 `bot/artifact` 访问。

Python 业务桥接仅在本机监听，核验宿主凭据。Bot 实验查询核验项目和功能归属；正式计划的来源从真实 Bot 会话解析后写入。草案、批准、执行和确认分别使用各自的业务动作。

## MCP 与执行边界

`research_mcp.py` 提供业务工具契约，Web 宿主以 `labweave_` 前缀注册当前开放的工具。会话归属由宿主解析，Python 服务再核验项目绑定。

| 类别 | 工具名 |
| --- | --- |
| 项目与资料 | `project_list`、`project_create`、`project_update`、`project_get_context`、`resource_search`、`resource_read`、`paper_read`、`paper_search`、`paper_citations` |
| 点子、目标与全局记忆 | `idea_create`、`idea_update`、`goal_create`、`goal_update`、`global_memory_search`、`global_memory_write` |
| 功能 Bot 与本机来源 | `feature_create`、`bot_assign`、`bot_assignment_index`、`sources_list`、`source_directory`、`source_read` |
| 任务、实验与评估 | `task_create`、`task_get`、`experiment_list`、`experiment_record`、`benchmark_list`、`benchmark_record` |
| 科研状态、证据与工作流 | `research_state_get`、`research_state_propose`、`evidence_search`、`evidence_add`、`evidence_link`、`workflow_list`、`workflow_get`、`workflow_draft` |

对话中的 `workflow_draft` 保存草案，协议和预算在项目代码沙盒批准。DSH 管理原生会话和 Agent 执行，`dsh_worker.py` 为 SDK 后台任务转交事件、审批和问题。

## 本地数据

- `demo/.local/workspace.sqlite3` 保存工作区状态和项目、任务、科研状态等业务数据；`demo/.local/projects/<project_id>/` 保存项目资源、仓库和实验产物。
- DSH Web 会话使用按数据目录划分的本机用户配置，早期 SDK 会话保存在 `demo/.local/dsh-home/`。备份位于 `demo/backups/`。具体路径见 [本机配置与历史目录](DSH前端适配路线.md#本机配置与历史目录)。
- `DEEPSEEK_API_KEY` 环境变量优先；也可使用 `demo/.local/deepseek.key`。不要将密钥、项目数据或虚拟环境提交到 Git。
- 后台订阅和复盘依赖本地服务运行；模型、论文检索和仓库克隆需要相应网络访问。当前没有跨设备云同步或远程实验调度。

## 开发验证

在仓库根目录使用 Python 3.12 运行 `python scripts/start.py --install-only` 安装固定运行依赖。启动方式及当前验证入口见 [README](../README.md)。基线验收使用 Python 3.12.6 和 DSH SDK/runtime 0.2.2rc2。

Windows 本地离线检查：

```powershell
.venv/Scripts/python.exe -m pip check
.venv/Scripts/python.exe tests/test_local.py
.venv/Scripts/python.exe tests/test_research_workflows.py
node --test tests/test_*.cjs
```

Linux 使用 `.venv/bin/python` 替换上面的解释器路径。浏览器测试需先按 `package-lock.json` 运行 `npm ci`；真实 DSH 集成需要已配置的 API 和网络，不能以离线测试结果代替。更完整的入口和现有验收边界见 `README.md`、`docs/dsh-runtime-validation.md`、`docs/V3科研闭环使用与验收.md`。
