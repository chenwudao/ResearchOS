# 开发基线与接口地图

本文记录 LabWeave 从 `codex/research-workspace` 的 ResearchOS V3 提交 `d0aa6e0` 继承的实现，供兼容性与迁移检查。它描述已有代码，不是未来架构计划。产品唯一前端主线为 DSH 原生 Web，现有自建界面只作为迁移回退；最新计划见 [DSH 前端适配路线](DSH前端适配路线.md)。现有 DSH 会话、项目数据、审批、实验闭环和证据网络均应作为兼容性基线保留。

参考资料：[项目规划对话](https://chatgpt.com/s/t_6afafb7812288191adc99a151e45a8d7) · [代码仓库（当前 GitHub 名称仍为 ResearchOS）](https://github.com/chenwudao/ResearchOS)。这只是仓库内的参考链接，不代表它们已添加到 ChatGPT 项目的 Sources。

## 目录与职责

| 位置 | 当前职责 |
| --- | --- |
| `scripts/start.py`、`start.ps1`、`start.sh` | 创建根目录 `.venv`、按 `requirements-runtime.txt` 安装依赖并启动服务；启动器要求 Python 3.12。 |
| `demo/static/` | 既有自建浏览器界面；`index.html` 是旧工作区入口，项目图、任务与科研闭环有独立脚本，迁移期间用于回退。 |
| `demo/api/main.py` | 本机 HTTP 入口、静态文件、旧版 skills 和 DSH bridge 路由。 |
| `demo/api/workspace_http.py` | `/api/workspace/` 路由、请求处理和本机同源检查。 |
| `demo/api/workspace.py`、`project_store.py`、`project_service.py` | 工作区状态、SQLite 中的项目结构及项目业务操作。 |
| `demo/api/tasks.py`、`dsh_worker.py`、`research_mcp.py` | 任务管理、DSH SDK 会话与事件、通过 stdio 提供项目 MCP 工具。 |
| `demo/api/automation.py`、`backup.py` | 后台动态和复盘任务、备份与恢复。 |
| `demo/api/research_api.py`、`research_ledger.py`、`research_workflows.py` | 科研状态、证据、实验工作流和人工确认。 |
| `demo/api/experiment_runner.py`、`experiment_worker.py`、`experiment_analysis.py` | 矩阵实验执行、子进程运行和结果分析。 |
| `skills/`、`examples/` | 现有科研技能说明和算法对照示例。 |
| `tests/`、`docs/` | 离线及集成测试、使用与验收文档。 |

## HTTP 接口

服务由 `demo/api/main.py` 绑定 `127.0.0.1:8765`。以下是入口地图，具体请求字段以对应处理函数为准；不要将其理解为已版本化的公开 API。

- `GET /api/health`、`GET /api/skills`、`GET|POST /api/skills/run/<name>`：健康信息及旧版示例技能。
- `GET /api/output`、`GET /api/output/<filename>`：旧版示例产物。
- `GET /api/dsh/status`、`GET /api/dsh/open`、`GET|POST /api/dsh/handoff`、`POST /api/dsh/launch-url`：保留的 DSH bridge 入口；`/api/dsh/launch_url` 是另一个拼写。普通聊天使用下面的工作区任务接口。
- `/api/workspace/` 的 GET：`state`、`status`、`tasks`、`automation`、`backups`；文件下载分别为 `resource/file/<projectId>/<resourceId>`、`backup/file/<archive>.zip`、`pdf/<id>.pdf` 和 `research/file/<projectId>/<workflowId>/<filename>`。
- `/api/workspace/` 的 POST：`state`、`resource/upload`、`resource/clone`、`resource/read`、`project/tool`、`backup/create`、`backup/import`、`backup/restore`、`tasks/create`、`tasks/respond`、`tasks/chat`、`tasks/approve`、`tasks/cancel`、`chat`、`automation/run`、`feed`、`experiment`、`pdf`。
- 科研闭环 POST 均以 `/api/workspace/research/` 开头：`overview`、`state`、`evidence`、`link`、`review-evidence`、`draft`、`approve`、`run`、`pause`、`cancel`、`accept`、`example`、`plan`、`log`。

`workspace_http.py` 检查 Host 和 Origin；除 PDF 和备份导入等特殊入口外，工作区 POST 接收 JSON 对象。实验草案、预算批准、运行和结果确认是不同动作；确认前不应把结果写成正式科研状态。

## MCP 与执行边界

`research_mcp.py` 注册下列工具，`project_service.call` 按传入的作用域分发。全局助手和项目助手使用的范围不同，变更时应保持项目隔离。

| 类别 | 工具名 |
| --- | --- |
| 项目与资料 | `project_list`、`project_create`、`project_update`、`project_get_context`、`resource_search`、`resource_read`、`paper_read`、`paper_search`、`paper_citations` |
| 点子、目标与记忆 | `idea_create`、`idea_update`、`goal_create`、`goal_update`、`memory_search`、`memory_write` |
| 任务、实验与评估 | `task_create`、`task_get`、`experiment_list`、`experiment_record`、`benchmark_list`、`benchmark_record` |
| 科研状态、证据与工作流 | `research_state_get`、`research_state_propose`、`evidence_search`、`evidence_add`、`evidence_link`、`workflow_list`、`workflow_get`、`workflow_draft` |

MCP 的 `workflow_draft` 只保存草案；协议与预算的批准以及执行入口在 HTTP 工作区。DSH 官方 Python SDK 管理原生会话，`dsh_worker.py` 将事件、审批和问题转交任务层；不要另造一套并行执行时或直接修改 DSH 会话文件。

## 本地数据

- `demo/.local/workspace.sqlite3` 保存工作区状态和项目、任务、科研状态等业务数据；`demo/.local/projects/<project_id>/` 保存项目资源、仓库和实验产物。
- `demo/.local/dsh-home/` 存放 DSH 原生会话；`demo/backups/` 存放备份。它们不属于版本控制内容。
- `DEEPSEEK_API_KEY` 环境变量优先；也可使用 `demo/.local/deepseek.key`。不要将密钥、项目数据或虚拟环境提交到 Git。
- 后台订阅和复盘依赖本地服务运行；模型、论文检索和仓库克隆需要相应网络访问。当前没有跨设备云同步或远程实验调度。

## 开发验证

在仓库根目录使用 Python 3.12 运行 `python scripts/start.py --install-only` 安装固定运行依赖；现有 `python scripts/start.py` 启动的 `http://127.0.0.1:8765` 是业务后端及迁移期旧界面，不是已完成的 DSH 产品入口。`README.md` 记录的原有验收解释器为 3.12.6，DSH SDK/runtime 为 0.2.2rc2。

Windows 本地离线检查：

```powershell
.venv/Scripts/python.exe -m pip check
.venv/Scripts/python.exe tests/test_local.py
.venv/Scripts/python.exe tests/test_research_workflows.py
node tests/test_merge.cjs
```

Linux 使用 `.venv/bin/python` 替换上面的解释器路径。浏览器测试需先按 `package-lock.json` 运行 `npm ci`；真实 DSH 集成需要已配置的 API 和网络，不能以离线测试结果代替。更完整的入口和现有验收边界见 `README.md`、`docs/dsh-runtime-validation.md`、`docs/V3科研闭环使用与验收.md`。
