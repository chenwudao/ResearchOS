# 开发基线与接口地图

Weave 使用 DSH `0.2.2rc2` 原生 Web 与 Python SDK。前端和宿主插件负责接入 DSH 能力，Python 业务服务负责项目、Bot、资料、状态与交付。整体架构见 [README](../README.md#技术架构)。

## 目录与职责

| 位置 | 职责 |
| --- | --- |
| [启动器](../scripts/native_launcher.py) | 准备 Python 环境、安装固定依赖、写入工作区 Web profile，启动业务桥和 DSH。 |
| [客户端](../plugins/dsh-labweave-workspace/client/) | 在原生 Web 插槽中呈现项目导航、Bot 对话与画布、项目任务和空间存储。 |
| [宿主](../plugins/dsh-labweave-workspace/host/) | 注册已认证的浏览器接口和工具，根据运行中的会话核验项目、访问模式和执行角色。 |
| [Python 业务桥](../demo/api/native_web.py) 与 [工作区绑定](../demo/api/dsh_workspace_map.py) | 接收本机宿主请求，核验可信的原生工作区 ID 和目录，并分发业务动作。 |
| [项目服务](../demo/api/project_service.py) 与 [Bot 目录](../demo/api/features.py) | 保存结构化项目记录、范式、Bot 配置、节点关系和资源。 |
| [分派存储](../demo/api/bot_dispatches.py)、[项目事件流](../demo/api/project_flow.py) | 保存任务、依赖、阶段草稿、正式交付、规则和成果的增量更新。 |
| [后台任务](../demo/api/tasks.py)、[SDK 进程](../demo/api/dsh_worker.py) | 运行按作用域绑定的 SDK 任务，转发事件、原生问题和审批。 |
| [项目工具 MCP](../demo/api/research_mcp.py)、[本机 HTTP MCP](../demo/api/mcp_http.py) | 提供共享工具契约。Windows 后台任务通过私有本机 HTTP 适配 MCP。 |
| [科研与证据](../demo/api/research_api.py)、[证据账本](../demo/api/research_ledger.py)、[运行记录](../demo/api/research_records.py) | 保存科研应用的状态、证据、实验与评估。 |
| [图表](../demo/api/visualizations.py) 与 [实验视图](../demo/api/bot_activity.py) | 校验结构化图表，预览表格数据，按项目与 Bot 读取已记录的运行和产物。 |

## 浏览器与业务桥接口

浏览器使用 DSH 的已认证 owner 连接调用 `/api/labweave/`。以下接口供随版本发布的客户端使用。

| 入口 | 作用域 |
| --- | --- |
| `catalog`、`create` | 获取已登记的工作区，创建并绑定项目。 |
| `project` | 从 `sessionId` 查询可信的会话及所属工作区，访问相应项目动作。 |
| `workspace-page` | 从登记的 `workspaceId` 查找项目，提供设置、Bot 页面、文件和项目内编辑。 |
| `project-handoffs` | 查询、确认及处理绑定发起会话和目标项目的转交。 |
| `conversation-activity`、`project-file-changes` | 投影会话和任务状态，以及归属明确的项目文件变更。 |
| `assistant-profile`、`assistant-history`、`conversation-rewind` | 管理全局助手资料、审核轨迹及原生会话撤回。 |

项目请求用 `action` 和 `args` 选择业务动作。Bot 与任务的读取包含 `bot_canvas`、`bot_dispatches`、`bot_dispatch_detail`。设置与外部本机来源使用 `settings/*` 和 `sources/*`，运行和产物使用 `bot/experiments`、`bot/experiment` 和 `bot/artifact`。Python 私有桥接仅在本机监听，二次校验宿主凭据、项目和工作区绑定。

## Tool、MCP、Skill 与 SDK

| 层 | 当前入口 |
| --- | --- |
| Tool | 有明确参数和结果的一次操作。DSH 提供获准的文件和命令操作，Weave 工具通过项目业务服务读写数据。 |
| MCP | 工具的协议入口。SDK 任务使用启动时绑定作用域的 MCP 服务，`tools/list` 与 `tools/call` 由同一工具分发器处理。 |
| Web 工具注册 | Web 宿主将适用的业务契约注册为 `labweave_*`，另外提供转交、Bot 分派、画布草稿等需要宿主状态的工具。 |
| Skill | 描述何时使用一种方法、怎么分步工作以及交付的标准。仓库的专项 Skill 和插件内的范式 Skill 加入运行时技能目录。 |
| SDK | 为后台任务启动或恢复 DSH 会话，接收事件、审批与提问。它与 Web 路径复用项目工具契约及范式 Skill。 |

第三方 MCP 服务通过 DSH 的配置接入，取决于实际 profile、传输和权限。用户在 Weave 里创建的项目插件是填入输入草稿的可复用指令。可执行的 DSH 插件通过上游插件系统装载。

| 领域 | 工具示例（业务名） |
| --- | --- |
| 项目与文件 | `project_list`、`project_create`、`project_get_context`、`resource_search`、`resource_read`、`sources_list` |
| Bot 与画布 | `feature_create`、`feature_layout`、`feature_entries`、`feature_push` |
| 点子、目标与记忆 | `idea_create`、`goal_create`、`memory_search`、`memory_write`、`memory_pin` |
| 文献与证据 | `paper_search`、`paper_lookup`、`paper_neighbors`、`paper_citations`、`paper_read`、`evidence_search` |
| 状态、实验与评估 | `research_state_get`、`research_state_propose`、`experiment_list`、`experiment_record`、`benchmark_record` |

工具清单和参数以 [业务工具声明](../demo/api/research_mcp.py) 与 [Web 宿主注册](../plugins/dsh-labweave-workspace/host/native.js)为准。项目主对话和 Bot 按角色及权限获得相应操作。

## 分派、澄清与数据关系

`project-leader.js` 在模型步骤前识别项目查询、执行和缺少必要条件的请求。需要确认时，`research-intake.js` 经 DSH 的 `userQuestions` 请求原生选项和自由输入，并用已提交的答案重新判断范围。后续科研阶段由 Skill 指导主对话使用 `ask_user_question`。子智能体将需要用户决定的事项交给发起会话。

`bot-delegation.js` 绑定项目、发起请求、任务 ID、承接 Bot 及权限。独立任务可并行，依赖任务读取前置成果。Bot 可发布阶段草稿，在交付时核验引用和实际状态。项目事件通过游标在下一模型步骤同步，已声明依赖的规则或成果变化会影响下游是否可以继续。用户确认的长期规则保存在项目记忆，主对话和同项目 Bot 可按需检索全文。

Bot 的主排布与范式数据共同保存。节点分支、普通关联和执行依赖分别来自 `parentId`、`relatedIds` 和 `dependsOn`。业务层校验关联范围与方向关系的循环。内容详情使用 `visualizations` 保存有限数量的实际数据点、图表类型和坐标信息。工程台也可读取 CSV/TSV 产物和实际运行指标序列。

## 文献服务

`paper_search` 默认查 Crossref 和 OpenAlex，可选择 arXiv 或 Europe PMC。交叉索引的结果按 DOI 和 arXiv 标识合并。设置 `includeStatus: true` 可以查看每个来源的响应状态。启动时可用 `OPENALEX_API_KEY` 配置 OpenAlex。

`paper_lookup` 核对 DOI、OpenAlex ID 或 arXiv 标识。`paper_neighbors` 使用 OpenAlex 返回参考文献与施引论文的索引计数和实际样本，`paper_citations` 使用 Crossref 的参考文献。`paper_read` 按页读取已登记的项目 PDF 或指定版本的 arXiv PDF，并返回来源定位。需要受限全文时，可导入已有访问权的 PDF。

## 本地开发和验证

在仓库根目录用 Python 3.12 运行 `python scripts/start.py --install-only`。Windows 使用 `.venv/Scripts/python.exe`，Linux 使用 `.venv/bin/python`。

```powershell
.venv/Scripts/python.exe -m pip check
.venv/Scripts/python.exe -m unittest discover -s tests
node --test tests/test_*.cjs
```

浏览器集成需要 `npm ci`。部分集成脚本使用模拟模型来验证真实 DSH 会话、业务路由和界面，真实模型测试需要可用的 API 配置。入口及本机数据目录见 [README](../README.md)。
