# 助手命名与作用域隔离

> 以下为 2026-11-17 临时预览阶段的历史验证记录。当前正式启动、项目会话和工具接入情况见 [DSH 原生工作区进度](DSH前端适配路线.md)。

## 产品约定

本分支以 DSH 原生 Web 前端为唯一产品前端，助手命名、项目管理与科研功能直接集成到 DSH；原自建界面仅保留为迁移期回退，不再作为独立前端产品发展。DSH 负责会话和 Agent 执行，LabWeave 后端负责科研业务和数据，不增加平行 Agent 运行时。

全局助手默认名称为 `goat`，用户可以重命名。项目名称由用户修改，不改变项目 ID。聊天、动态、点子、目标、资源库使用稳定的功能 ID；显示名称可由全局或项目对话中的助手工具调整。全局对话可以调整全局默认名称，也可以明确指定项目；项目对话只能调整当前项目。项目覆盖优先于全局默认。

## 已实现的后端基础

- `naming.py` 将助手名称、功能显示名称及功能名称变更记录保存在 SQLite，空名称和无效名称会被拒绝。五个功能 ID 不随显示名称变化。
- 本地工作区服务提供助手名称的读取和直接更名接口，沿用工作区 Host 和 Origin 校验。DSH 插件通过 `connection.fetch` 提供只代理助手名称的同源接口；不代理项目列表、模型密钥或整个工作区快照。插件代码还在原生常规设置中注册更名项，并在侧栏品牌下显示名称，不增加重复的助手会话按钮。
- 现有 SDK 任务的 MCP 入口提供 `assistant_name_get`、`assistant_rename`、`feature_labels` 和 `rename_feature` 工具。作用范围来自启动任务时固定的服务端 scope，而不是工具参数中的身份；通用项目工具 HTTP 接口不提供功能改名操作。
- `dsh_workspace_map.py` 为独立全局工作区和项目工作区提供显式绑定，验证路径并拒绝重复绑定、越界、失效或未知映射。会话范围解析需要调用方提供可信的 DSH 会话到工作区查询。

MCP 是对话工具入口，并不证明请求者在密码学意义上一定是 LLM：能取得该任务 MCP 凭据的客户端也可能调用它。用户要求的对话驱动变更依赖受信的会话调度和工具授权，不能通过接受客户端提交的 `actor` 字段实现。

## 验证与未完成的接入

隔离测试覆盖默认及自定义助手名、全局与项目名称覆盖、项目之间拒绝越权、并发绑定、路径失效和真实本机 MCP 作用域。Windows 测试环境没有创建目录符号链接的权限，相关测试跳过。DSH owner 连接上的名称代理已用隔离 profile 与模拟后端测试授权、匿名和伪造来源。固定版 DSH 浏览器中验证了默认名称、原生设置中保存、侧栏即时更新，以及 900×700 窗口；不代表用户真实运行中的旧服务已经载入新代码。

目前这些能力尚未完整连到 DSH Web：现有预览使用临时 profile，顶部原生新建会话仍继承当前或最近工作区；当前运行中的旧服务尚未加载助手名称接口。原生项目名称与本地项目名称尚未同步。固定版 DSH 的内置侧栏替换与 session 作用域仍需验证。不能将根级共享 MCP 当作项目隔离，也不能从浏览器或模型提供的项目 ID 推断当前会话权限。

下一步是以持久 profile 建立可信的全局工作区、项目工作区和会话映射；在 DSH 侧栏安全呈现并同步 `goat` 与项目名称；将按会话作用域隔离的工具接入原生 Web，之后再按插件方式接入项目内的五项功能。尚未通过真实多项目端到端测试前，不应宣称 Web 会话已经隔离。
