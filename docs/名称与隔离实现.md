# 助手命名与作用域隔离

当前启动方式与验证范围见 [工作区适配记录](DSH前端适配路线.md)。早期临时预览的环境与记录见 [原生工作区隔离验证](DSH科研项目映射验证.md)。

## 产品约定

Weave 通过 DSH 原生 Web 提供助手命名与项目功能。DSH 管理会话和 Agent 执行，Weave 业务服务管理项目及其业务数据。

全局助手默认名称为 `Weave`，用户可以重命名。项目名称由用户修改，不改变项目 ID。聊天、动态、点子、目标、资源库使用稳定的功能 ID；显示名称可由全局或项目对话中的助手工具调整。全局对话可以调整全局默认名称，也可以明确指定项目；项目对话只能调整当前项目。项目覆盖优先于全局默认。

## 已实现的后端基础

- `naming.py` 将助手名称、功能显示名称及功能名称变更记录保存在 SQLite，空名称和无效名称会被拒绝。五个功能 ID 不随显示名称变化。
- 用户可在助手资料面板更改名称，在项目设置中编辑项目名称。DSH 插件通过 `connection.fetch` 提供已认证的同源业务入口。
- 对话工具提供 `assistant_name_get`、`assistant_rename`、`feature_labels` 和 `rename_feature`。Web 宿主使用真实会话和已登记工作区确定作用域。SDK 后台任务使用启动时绑定的服务端作用域。
- `dsh_workspace_map.py` 为独立全局工作区和项目工作区提供显式绑定，验证路径并拒绝重复绑定、越界、失效或未知映射。会话范围解析需要调用方提供可信的 DSH 会话到工作区查询。

MCP 是对话工具入口，并不证明请求者在密码学意义上一定是 LLM：能取得该任务 MCP 凭据的客户端也可能调用它。用户要求的对话驱动变更依赖受信的会话调度和工具授权，不能通过接受客户端提交的 `actor` 字段实现。

## 验证

隔离测试覆盖默认及自定义助手名、全局与项目名称覆盖、项目之间拒绝越权、并发绑定、路径失效和真实本机 MCP 作用域。Windows 测试环境没有创建目录符号链接的权限，相关测试跳过。DSH owner 连接上的名称代理已用隔离 profile 与模拟后端测试授权、匿名和伪造来源。固定版 DSH 浏览器中验证了默认名称、原生设置中保存、侧栏即时更新，以及 900×700 窗口；不代表用户真实运行中的旧服务已经载入新代码。

已登记的全局工作区和项目工作区使用持久配置。顶部新会话进入独立的全局工作区，项目聊天通过所属工作区读取数据。Bot 工作台的实验和产物接口同时按项目与功能归属核验，相关浏览器用例覆盖两个项目中的同名 Bot。
