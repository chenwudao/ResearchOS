# Weave 的 DSH 前端适配路线

## 当前交付

科研工作区基于固定版 DSH 原生 Web。Windows 和 Linux 从项目根目录启动同一 Python 业务服务和 DSH 运行程序。业务服务保留已有 SQLite、项目文件、科研记录、任务审批及 SDK 历史；旧自建前端及 `--legacy` 回退入口已移除。

| 入口 | 已接入的行为 |
| --- | --- |
| 顶部助手 | 左上角打开独立的全局助手，默认名称为 Weave。可选择历史对话。点击助手头像从右侧打开资料面板，头像和连接状态固定在面板顶部。 |
| 助手模型 | 智能选择在本机根据当前输入的复杂度、对话长度和模型能力为每轮选择模型、推理档位及上下文窗口。固定模式保存这三项设置。上下文上限交由 DSH 管理并受模型能力约束，项目聊天与 Bot 沿用各自的设置。 |
| 品牌头像 | 展开和收起的侧栏、全局与项目聊天首页、回复生成状态、浏览器标签和安装图标统一使用星球轨道标识。 |
| 会话模式 | 日常聊天直接使用已配置的 DSH 工具预设。新会话的预设选择器与会话标题的模式标签在科研界面中收起；设置里仍可选择默认预设，插件开发可显式使用创造模式。模型选择、工作区权限与实验预算审批由各自的组件负责。 |
| 原生工作区 | 加号打开「新建工作区项目」。新项目先显示「聊天」，按需添加功能 Bot，已有栏目随项目保留。 |
| 项目设置 | 项目行的齿轮打开设置，可编辑名称、简介和研究主题，并关联本机来源文件夹。文件保留在原路径，项目助手和 Bot 使用项目专属只读工具查看目录、读取文本和 PDF。移除来源只撤销关联。 |
| 项目聊天 | 通过 DSH 执行上下文和宿主注册表核验会话归属，支持点子、目标、资源、科研状态、实验草案和证据。 |
| 项目聊天入口 | 点击「聊天」切换历史列表的展开状态，并打开该项目的 DSH 原生空白对话。已有空白草稿直接复用，缺少草稿时由 DSH 准备一个。发送首条消息后才出现在聊天历史。 |
| 消息撤回 | 全局助手、项目聊天和功能 Bot 都可以在消息旁撤回提问或答复。撤回会截断该处及后续对话的模型上下文。撤回提问会把文字加回草稿，撤回答复会保留先前的提问。 |
| 对话权限 | 「助手设置 → 助手权限」从下一轮起应用于全局助手，默认仅可查看。功能 Bot 在每轮开始时读取同项目最近提问或调整过权限的主聊天，项目主聊天通过输入框选择本次会话的权限。 |
| 对话进度 | 全局助手在当前回复的消息区域显示等待响应、推理、工具处理和生成回复等状态，附上提问摘要与耗时。项目主聊天在同一位置显示「深度思考中」。功能 Bot 也在消息区域显示本轮进度，并可从那里打开原生审批界面。 |
| 项目栏目 | 左侧栏目控制 DSH 主区域的独立页面。聊天页列出本项目对话，动态、点子、目标和资源库分别使用对应的列表、编辑和阅读控件。栏目 ID 固定，支持在侧栏功能行、功能页标题栏、通用设置或通过对话工具按项目修改显示名。 |
| 功能 Bot 工作台 | 功能页右上角打开右侧弹窗，显示本项目中这个 Bot 的备注、关键词、任务线程与实验线程。「任务」管理定时任务和 Markdown 分工，可查看实际投递并进入对应对话。「实验」按项目与 Bot 展示试跑和正式计划，预览日志、图片及数值表。「工具」打开原生浏览器和项目代码沙盒。 |
| 自动化 | 原生任务管理页使用独立全局工作区作为默认目标，支持显式选择项目。项目对话列出的任务按实际投递目标过滤，编辑需要匹配版本。项目聊天右上角的「项目任务」汇总本项目各 Bot 的定时任务，显示已启用数量，点击任务可打开原生详情。 |
| 更多 | 创建指令插件时必须选定项目或全部项目。每次调用在当前项目内生成聊天草稿。 |
| 启动与恢复 | 根目录启动器管理本机服务和持久化 Web 配置。关闭后可备份和还原业务数据库、个人项目目录、原生工作区、会话及任务。 |

## 本机配置与历史目录

Weave 使用 DeepSeek Harness SDK/runtime `0.2.2rc2`。Windows 的网页设置及会话位于 `%LOCALAPPDATA%\LabWeave\web`，Linux 位于 `${XDG_STATE_HOME:-$HOME/.local/state}/LabWeave/web`，按科研数据目录区分子目录。早期 SDK 会话存储在 `demo/.local/dsh-home/`。

DeepSeek 密钥依次取自 `DEEPSEEK_API_KEY`、`demo/.local/deepseek.key` 和本机用户配置。Windows 用户配置为 `%LOCALAPPDATA%\LabWeave\deepseek.key`，也兼容 `%USERPROFILE%\.labweave\deepseek.key`。Linux 使用 `${XDG_CONFIG_HOME:-$HOME/.config}/labweave/deepseek.key`。Windows 的 `LABWEAVE_WSL_DISTRO` 可指定执行项目代码的 WSL 发行版。

## Weave 品牌适配与验证

登录成功后的原始 HTML 标题通过 `webServer.tapIndex` 设置。根页面的 401 由 `connection.authorizeIndex` 在 HTML 渲染前生成，适配器只替换固定版本的登录提示正文。升级运行时后可用 `python tests/integration_shell_brand.py` 验证匿名响应、登录跳转、Cookie、标题和图标。

首次使用通过原生 `settings.onboarding` 插槽直接提供模型 API 配置。移除 `welcome-notice` 预览说明，并将 `deepseek-official` 引导替换为使用原生模型目录、设置与凭据接口的 Weave 配置表单。用户只需选择模型供应商并填写对应的 API Key，地址和模型沿用供应商预设，也可稍后配置。已有可用模型时直接进入工作区。

账号、设置和错误提示按翻译命名空间与消息键适配，在原始模板上处理名称后再插入参数。科研工具的原生卡片复用活动记录的动作名称，仅调整系统生成的摘要前缀。工具标识、用户消息、项目与助手的自定义名称、审批参数及历史记录均保留原值。模型提供方继续按实际账号和 API 类型显示。

`python tests/integration_native_web.py` 使用临时工作区覆盖八种内置语言的首次 API 配置与设置、项目改名、资料原文、旧定时任务及重启恢复。`python tests/integration_model_config.py` 验证首次配置 API、重新打开及在本机模拟服务上实际调用科研工具，检查卡片的名称和参数。这一轮还在 Chromium 的 80%、100%、125%、150% 浏览器缩放下核对了侧栏图标和名称。第三方插件自行生成的内容及外部账号网站由各自提供方维护。

## 实现与隔离

Weave 插件位于 `plugins/dsh-labweave-workspace`，包 ID 为 `labweave-research-workspace`。`client/` 通过 DSH 的插槽接入项目侧栏、主面板、聊天和「更多」菜单。`host/` 注册本地科研接口、原生对话工具及品牌资源。主题、会话消息、输入框、模型选择和快捷键沿用 DSH。

从双插件版本启动升级时，启动器在原 Web 配置中更新 Weave 插件文件，并从 `profiles/web/package.json` 的加载列表和依赖中移除 `labweave-dsh-prototype`。升级沿用原配置目录、工作区、会话和定时任务标识，以及 SQLite、项目文件、模型配置和凭据。

宿主从 `exec.agent.session` 取得正在执行的真实会话，与 DSH 会话服务核对，再通过 `workspaceRegistry` 的成员关系查找工作区。私有业务服务核对 SQLite 绑定、项目存在和项目目录。未知会话、重复绑定、路径不符以及项目内工具指定其他项目都会被拒绝。浏览器上的操作走 DSH 已认证的 owner 连接，项目内功能改名仅允许作用于已绑定的当前项目并保持功能 ID 不变。本地文件和终端操作继续遵守 DSH 的访问模式与用户审批。

全局工作区使用稳定目录 `demo/.local/web-global`。DSH 内部保留固定的默认工作区标识，原生自动化表单据此选择全局目标。项目目录仍为 `demo/.local/projects/<projectId>`。已从 DSH 移除的原生登记不会被静默改绑到新会话。旧 SDK 历史仍保留在 `demo/.local/dsh-home`，新 Web 会话继续保存在专属 profile。

## 项目聊天右侧工具栏

项目主聊天通过「工具」打开右侧栏。原生工作区文件面板负责浏览项目目录，右侧栏同时提供原生终端、浏览器及两个项目工具。

| 工具 | 用途 |
| --- | --- |
| Git | 查看项目仓库和工作树的分支、变更文件与最近提交。 |
| 项目代码沙盒 | 查看剩余试跑预算及下次试跑环境，在折叠设置中创建环境和授权预算。通过「试跑」与「正式实验」查看运行列表及详情，包括日志、产物或实验报告。 |

在项目主聊天提交试跑或正式计划时，右侧栏自动打开并选中对应详情。全局助手可为明确指定的项目调用实验工具，运行记录在目标项目的沙盒中查看。功能 Bot 工作台可查看自己的实验并跳转到项目沙盒。运行环境与授权流程见[功能 Bot 与项目代码沙盒](功能Bot与项目代码沙盒设计.md)。

## 验收与范围

- `tests/test_native_web.py` 覆盖已有项目、作用域越权拒绝、局部与共享插件，以及含原生会话的备份和回滚。
- `python tests/integration_native_web.py --rightbar-only` 使用临时项目检查工具入口、原生文件面板、图标、空沙盒和试跑授权。另在 Chromium 中以 1040 像素宽窗口、深色主题及 125% 和 150% 浏览器缩放核对试跑与正式实验详情，详情中的已完成日志和产物使用样例数据。
- `tests/integration_native_web.py` 启动真实 DSH 与浏览器，使用两个临时项目验证交互并重启。启用 `--model` 时，在项目乙内实际调用模型修改栏目名，并在全局会话中查两个项目。
- `python tests/integration_conversation_rewind.py` 使用固定版 DSH 与本机模拟模型验证三个聊天入口、草稿恢复和后续请求上下文，覆盖页面刷新、服务重启、深色主题和 125% 页面缩放。会话空闲时，可以撤回仍在当前上下文中的消息。再次发送时可重新添加附件。
- `python tests/integration_bot_workbench.py` 使用两个项目里的同名 Bot 验证工作台的数据隔离、原生浏览器、正式计划归属及定时任务的新建、编辑、删除和实际投递。试跑产物预览使用样例文件。
- 撤回浏览器用例还覆盖全局权限跨重启生效、已有 Bot 随主聊天切换权限、仅可查看模式下拒绝实验试跑，以及助手资料入口、全局助手与项目主聊天的思考位置、Bot 的进度文案。Bot 跳转到交互审批的流程需要单独验证。
- `python tests/integration_plugin_upgrade.py --old-root <旧版代码目录>` 在临时配置中先用双插件版连接自定义模型、创建项目和会话，并安排绑定该会话的定时任务。再用单插件版启动同一配置，检查项目和会话标识、原定时任务、深色主题和模型配置，以及旧会话续聊和新会话默认模型。本次在 Linux、Chromium 和 DSH `0.2.2rc2` 上通过，模型请求使用本机 OpenAI 兼容模拟服务。
- 使用 `python -m unittest discover -s tests` 检查业务与实验闭环。Windows 子进程冷启动可能需要几十秒，实验严格按批准的总预算和每次运行时限执行。测试的真实进程预算单独配置。
- 用户创建的项目插件目前是可复用的科研指令。具有可执行代码的 DSH 扩展仍使用上游插件管理及权限。多篇论文对比、DOI 引用图和实验记录已接入原生资源库；旧版独立静态界面已不再保留。
- 本次验证覆盖固定运行版本。系统级高 DPI、所有第三方插件组合以及跨机原生会话路径迁移需要分别验证。

此前的实验结果保存在 [原生预览记录](DSH原生隔离预览.md) 和 [工作区映射验证](DSH科研项目映射验证.md)。固定版本的上游实现见 [DSH 发布快照](https://github.com/deepseek-ai/deepseek-harness/tree/dsh-v0.2.2-rc.2)。
