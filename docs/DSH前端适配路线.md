# LabWeave 的 DSH 前端适配路线

## 产品主线与当前状态

本分支的唯一前端产品主线是在固定版本的 DSH 原生 Web 前端上建设 LabWeave 科研工作区：优先使用上游插件、插槽和现有服务；若公开扩展点不足，采用可维护、版本锁定并经过验证的 DSH 局部修改。取消另建或并行开发独立产品前端的计划，也不另建与 DSH 并行的 Agent 运行时。LabWeave 后端继续负责科研业务、数据和必要的作用域控制。

当前仍有历史自行维护的 `demo/static/` 界面，通过 Python 后端调用 DSH SDK；它不是 DSH Web 界面。它只作为迁移期间的现有能力与数据回退，继续保障可用，不作为新功能前端或产品主线。现有业务数据由 LabWeave 管理，不能因为切换界面而直接视为 DSH 的原生工作区数据。

本项目锁定 `deepseek-harness-sdk==0.2.2rc2` 和 `deepseek-harness-runtime-bin==0.2.2rc2`。在 Windows 的临时隔离 `DSH_HOME` 中，已验证该运行包支持 `dsh web --help`，并可使用 `web --port 0 --no-open` 启动本机 Web 服务；通过其临时启动链接请求页面得到 HTTP 200 和 HTML。页面启动清单包含侧栏、模型设置、主题、快捷键和插件管理等客户端模块。[LabWeave 插件原型](../plugins/dsh-labweave-prototype/README.md) 保留 DSH 原有工作区和会话，在侧栏显示全局助手名称并在原生设置提供改名；默认 `goat`、设置保存及显示同步已在隔离 profile、模拟后端和 900×700 窗口验证。当前运行中的旧服务尚未自动加载这些更改。**这尚未验证所有设置、浏览器缩放、科研业务接入或现有会话迁移**。

DSH 官方当前文档描述了基于 Cordis 的插件式 Web 客户端和 React 插槽系统，可向已声明的界面位置贡献组件；上游 Web 客户端包含聊天、侧栏与设置等模块。官方仓库采用 MIT 许可证，并注明依赖的第三方许可；上游仍处于开发预览，可能出现不兼容变更。当前上游 `master` 文档不能单独证明每个插槽在本项目锁定版本中均可使用，应在锁定版本中逐项验证。

相关上游资料：[项目及许可](https://github.com/deepseek-ai/deepseek-harness)、[Web 客户端架构](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/subsystems/web-client.md)、[界面插槽](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/subsystems/slots.md)、[客户端模块清单](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/client/README.md)。

## 当前聊天链路的验证

2026-11-17 的隔离检查中，原 Windows stdio MCP 接入会导致 DSH 初始化超时；项目 MCP 单独运行时可完成握手。现已增加 Windows 每任务本机 HTTP 桥接，并在隔离项目中验证 DSH 实际调用项目列表和创建点子；Linux 保留原 stdio 路径。桥接使用随机端口和临时令牌，项目作用域不变。冷启动约需 40 秒，热启动约需 5–9 秒；用户实际使用的网络和机器状态可能影响耗时。模型启动的 shell 子进程是否继承临时令牌仍待独立确认，不能把这一边界视为已验收。

## 迁移原则

- 最终用户在本机启动 LabWeave 后端及所需服务，浏览器直接展示 DSH 原生 Web 主界面；科研空间通过原生扩展融入其中，统一启动与停止相关本地进程。隔离预览和跳转旧界面只用于迁移期间，不是最终产品形态。
- 以固定版本的 DSH Web 为唯一产品前端，优先复用其聊天、会话、设置、快捷键和界面组件；LabWeave 增加科研工作区所需的插件和业务服务。DSH 扩展点不足时，允许对 DSH 做版本锁定、可维护并经过验证的局部修改；不得因此另建平行前端或 Agent 运行时。
- 保留当前 LabWeave Python 业务服务、项目目录与 SQLite；先让新入口读取现有数据，再逐项切换写入，不能把两套数据库或会话视为自动互通。
- 现有 DSH SDK 使用 `demo/.local/dsh-home`、`sdk` profile 和项目作用域 MCP 工具；DSH Web 的 profile、会话和配置能否安全复用，必须通过备份后的隔离副本验证。不要直接覆盖用户原有 DSH 配置或会话。
- 浏览器本身提供页面缩放，但 DSH 的每项缩放设置、不同窗口尺寸和高 DPI 布局仍需实际测试；不应承诺切换宿主后自动满足所有体验要求。

## 前端布局约定

依据此前《科研产品定位分析》中的方案，并结合后续“以 DSH 原生界面为基础、最小改动”的要求：

- 左侧直接将 DSH 既有工作区改造成科研项目创建与进入的区域，保留项目下的会话、搜索、创建和设置等原有交互；不额外增加一份平行的科研项目列表。目标是让顶部“新建会话”成为独立全局助手对话入口，不增加重复按钮，也不自动带入当前项目上下文；目前固定版本的原生行为仍会继承当前或最近工作区，尚待改造和验收。
- 中间以聊天为主；全局助手与项目内聊天分开，进入项目后其聊天使用该项目的上下文和项目助手。不得把尚未连接上下文的聊天标成项目助手。
- 每个项目内组织聊天、动态、点子、目标、资源库五项功能；这些是围绕当前聊天显示或操作的科研内容，不应默认铺成五个大型仪表盘。实验能力保留并逐步融入项目工作流。
- 右侧仅在需要时展示任务计划、运行状态、结果或关联资源，闲置时不强占主聊天区域。窄屏时以可关闭面板或等效的原生交互呈现。
- 用户指定的界面显示标题为 `leaweave`；全局助手名称默认为 `goat`，用户可更改，项目也可更名，功能插件使用稳定 ID、其显示名通过全局或项目内助手对话工具调整。当前仓库、目录和已有产品文档仍使用 LabWeave，不据此擅自重命名文件或数据。
- 每个科研项目需要可继续对话的项目助手，并以项目上下文连接原生会话；在项目映射与数据隔离得到验证前，不把普通 DSH 会话声称为已经绑定项目的科研助手。
- 自动化支持独立全局任务，也支持明确选择一个科研项目；执行时按选定范围加载上下文与权限，不能按最近打开的项目推断。项目功能应可按插件方式扩展，插件可选择单个项目或全部项目生效；“全部项目”的执行仍逐项目隔离。插件创建、启用、配置与权限以经过验证的 DSH 扩展能力为基础。
- 项目切换、项目会话、五个栏目和右侧任务面板需要分别接入并验收，不能把布局目标说成已全部实现。

## 分阶段实施

1. **稳定 DSH 基础**：维持固定版本，在独立配置中验证原生聊天、会话、设置、主题、插件和窗口缩放；保留现有界面和数据作为迁移回退。此前的隔离启动和助手名显示/设置已验证，完整设置与缩放仍待验收。
2. **建立全局与项目隔离**：在持久 DSH profile 中建立独立全局助手与科研项目工作区/会话的可信映射，顶部新建会话进入全局助手，项目会话保持所属项目作用域。接入并验证会话范围内的项目上下文、MCP 工具和权限；不依赖当前页面、最近项目或浏览器传入的 ID 推断权限。
3. **在 DSH 内接入科研功能**：直接改造原有工作区为项目的创建和导航入口，在同一聊天界面中逐项接入聊天、动态、点子、目标、资源库和项目作用域插件；支持项目名、助手名以及通过对话工具调整的功能显示名。保留原有实验、证据、任务和备份能力，不新建并行项目列表或独立前端。
4. **统一启动并验收**：稳定启动本地业务服务和 DSH Web，使 DSH 成为默认入口；验收设置、窗口缩放、历史数据、项目隔离、会话恢复、审批、自动化、插件范围、资源导入、备份恢复及 Windows/Linux 安装升级。迁移未验收前继续保留旧界面回退和全部数据。

## 接口与安全边界

LabWeave 当前 HTTP 服务与 DSH Web 通常使用不同端口，现有工作区接口检查 Host 和 Origin。插件与业务服务的通信需要设计受控的宿主桥接和明确授权，不能假设浏览器跨端口请求、DSH 登录状态或会话自动共享。

固定版 `@deepseek-ai/dsh-host-webserver@0.2.2-rc.2` 的自定义路由类型不包含 `auth` 字段；隔离实验确认设置 `auth: 'required'` 仍会让未登录请求读取测试响应。不得依赖该字段保护项目数据；在确认可用的宿主认证方式并通过匿名与恶意来源测试前，不得通过自定义路由暴露真实项目。密钥、临时登录链接和用户项目数据不得写入代码或示例日志；真实模型和插件验证使用单独测试数据。
