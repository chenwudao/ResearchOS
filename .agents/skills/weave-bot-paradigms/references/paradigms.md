# Weave Bot 范式元素与前端参考

以下是已确认的五个范式和十个独立单元示例。LLM 根据任务提取其中有用的元素，选定一个受支持的排布。字段名称用来描述数据含义，实现时与项目已有模型对齐。每项工作或成果可带项目归属、稳定引用、出处和真实状态。

| 范式 | 可用排布与主要元素 | 示例单元 |
| --- | --- | --- |
| **目标** | **分类清单**组织可勾选的目标、状态、优先级、截止时间和完成条件，分组依据从任务中提取。**目标路径**按真实依赖显示前置、当前步骤、阻塞和交付点，已知日期作为补充。 | 「本周待办」按优先级整理组会准备。「组会交付路径」从确认指标到试跑、正式实验和交图。 |
| **笔记** | **资料库**采用网盘式分类树、聚类或分组文件列表，显示目录路径、资料类型、标签、摘录、原件和来源关联。**历史跟踪**以更新时间倒序显示新增、修订和推送事件，事件含时间、动作、摘要和附件引用。 | 「文献资料库」按文献、数据协议和实验笔记归档。「论文追踪」展示新增论文、改动摘录和导入文件。 |
| **思维导图** | **关系图**显示知识、方法或文献节点与带类型的关系，点选节点或连线后可看依据和出处；推断关系标明待核查。**文献脉络**按发表时间或有依据的研究阶段排列代表文献、范式变化和分支，显示原始来源。 | 「持续学习方法图」展开数据回放、正则约束和参数隔离。「文献演进脉络」沿研究阶段串起代表工作。 |
| **点子** | **发散探索**围绕一个问题展示多个可尝试分支，每个分支给出假设、具体操作和最小验证。**线性推演**按观察、解释、验证和下一步排列，允许记录不同验证结果的后续动作以及建议的迭代依据。 | 「回放方向探索」并列均衡采样、动态缓冲区和关键轨迹。「样本失衡推演」沿一项解释逐步验证。 |
| **工程台** | **并行运行**按方法、种子或配置排列实际运行，显示状态、日志、指标、结果图和产物。**顺序流程**按依赖、检查门槛和批准的优先顺序展示步骤，显示待审批、运行中、失败或完成，以及相关代码、环境和记录。 | 「种子并行对照」用方法和种子矩阵显示运行与结果。「复现实验流程」按环境检查、试跑、审批、正式运行汇总展开。 |

## 项目扩展范式

语义描述定义内容及展示逻辑。例如「按更新时间追踪数据集版本和授权变化，授权待核对时保留说明」。对应的定义可以选「文件动态」排布，元素为「数据集」「版本」「授权」「变更说明」。元素值随 Bot 记录保存。相同定义可以给本项目多个 Bot 使用，每个 Bot 保持独立的名字和记录。

手动新增时填写范式名称和语义描述，选择一种排布，并为每个字段指定名称、值类型和展示用途。项目对话可以提交同样的定义。字段支持文本、数字、日期、是／否、HTTP(S) 链接和同 Bot 记录引用。主标题、摘要、分组、时间位置、状态、原始来源、关联记录各可映射一个字段，其他字段进入详情。旧版只保存名称的字段继续作为文本详情读取。

- 时间线按有效事件日期排序，笔记更新流由新到旧，文献脉络由早到晚。映射了日期字段却没有提供值时，记录保留并标记「日期待确认」。文献脉络的日期来自记录的实际发表或事件日期。
- 目标路径依据已登记的前置依赖排序，未完成前置项时标明阻塞。清单以分类或优先级分组，并显示实际完成进度和完成条件。
- 导图根据记录引用呈现分支，连接可以标出关系类型、核查状态和来源。点子突出假设、最小验证与结果，页面按分支或推演顺序展开。
- 工程台把试跑、实验计划和有关记录放在同一个入口。流程详情按真实阶段依赖绘制连线，并行运行按方法排列种子、预算和状态。日志、指标和产物从实际运行记录读取。

## 画布与对话

Bot 的主排布放在上方画布，对话与输入放在下方。沿用项目原生字号、背景和控件。画布支持内部缩放、拖动平移和重置，拖动水平分隔线只分配两区的高度。画布中的线取自已存记录的依赖和关联。聚类成员可按各自名称筛选，记录仍归属其原 Bot。

点击节点打开详情，可查看文档、文件和来源。动态栏的外部原文可通过弹窗浏览，其他范式的记录使用普通详情。删除记录会清理关联连线，保留已存的项目原件。

## 决策与聚类示例

- **建笔记单元。** 「持续跟踪新论文，每次能打开原件」提供跟踪主题、更新事件和论文引用，适合「论文追踪」的时间流。「把已有论文按研究方法归档」提供分类依据、目录和文件引用，可以创建「文献资料库」。
- **聚类笔记单元。** 「把论文追踪、方法摘录和数据集笔记聚成写综述用的大 Bot」指定了同范式成员和聚合目标。可以建立「VLA 研究资料」，选一套方法分类树，以资料 ID 去重，保留每条摘录、原文件和历史事件的成员来源。历史事件可在相应资料详情回查。
- **保持跨范式边界。** 笔记里的论文可以成为导图的来源。点子里的尝试可以成为目标的待办或工程台的实验输入。交接传递记录或产物引用，各范式按自己的方式渲染。
- **执行与展示对齐。** 「先确认环境，再并行做三个种子」可以选择顺序流程作为工程台主排布，把并行运行作为正式阶段的内容。运行计划、并发和审批以现有业务服务为准。
