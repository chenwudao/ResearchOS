# Weave 科研 Bot

遵守仓库的 [AGENTS.md](../../../AGENTS.md) 和 [科研 Bot 与项目上下文需求](../../../docs/科研Bot与项目上下文需求.md)。涉及前端、创建或聚类时，读取 [范式元素与前端参考](references/paradigms.md)，用其中的十个示例检查单个 Bot 的职责、元素和唯一主排布。示例是设计基线。项目可以按实际需求只使用其中部分范式，同范式的实例也可以采用同一种排布。

## 角色与同步

- **LLM Boss** 负责底层理解、拆解和决策。**Weave Manager** 对应全局助手，按用户指定或对话中已明确的项目协调工作。**Project Leader** 对应项目主对话，选择和分派 Worker、处理依赖、汇总进度。**Bot Worker** 在分配的范式和项目权限内产出成果。这些角色复用项目现有内核运行时和会话入口。
- Leader 将相关的实时对话记录、项目记忆、决定和进度写入同项目共享状态，并向所有 Worker 发布更新。Worker 接单和执行下一步前读最新状态，回报进度、阻塞和成果引用。任务依据变化时把差异回报 Leader，由 Leader 决定延续、修订或暂停。
- 助手与 Bot 共用同一套插话机制。用户可在当前会话点名有权参与的角色，已参与同一任务的角色也可在有需要用户关注的事项时主动发言。Leader 协调顺序。插话使用真实发言者，带原消息或任务关联，持续保存在发起任务的会话。按目标会话校验项目权限，并对重复投递去重。
- 项目对话和所有 Bot 通过同一项目范围读取和更新记忆与规则。用项目上下文提供有限的核心要点，再按当前任务主动检索完整记录。用户确认的项目规则按 `rule` 类别保存并置顶，复用现有记忆 ID 修订规则。全局助理查自己的记忆，项目回查采用对话已明确的项目。
- 用户与 LLM 在对话中确定项目需要哪些范式、每类有几个单元及各自的职责。职责匹配且仍适用时复用已有单元。需要独立跟踪的职责可以新建。临时交付优先进入已有职责匹配的单元。

## 从对话决策到一个 Bot 单元

1. 从任务目标、明确约束、相关记忆和最新项目进度提取决定。决定至少含目标项目、操作、范式、Bot 名称、职责范围、一个主排布，以及支撑该排布的任务元素和来源。根据操作带上已有 Bot、成员或成果的引用。
2. 按范式判断元素是否支撑这项任务。由 LLM 组装经过校验的结构化元素，前端用对应的项目组件渲染。信息不足时保留待补，或选一种当前信息能支撑的排布。运行状态、审批、时间、证据和文件来源分别取自有权访问的真实记录。
3. 在项目服务校验范式、排布、元素、项目归属和引用。保存 Bot 的稳定 ID、范式和单一排布。普通任务更新内容；聚类、职责变化等明确的组织决定可以重新确定主排布。
4. **创建**从一个独立单位开始。手动入口沿用项目侧栏创建方式，只收集所选范式和名字，LLM 根据对话与项目上下文决定职责、排布及初始元素。
5. **聚类**把几个同项目、同范式的小 Bot 组织成一个同范式的大 Bot。决定中给出成员、承接 Bot、聚合职责、一种排布和元素归并方式。聚合后以大 Bot 作为统一入口，保留成员身份、来源、会话与已产生的记录引用。按稳定引用去重，归并前厘清未完成任务和定时跟踪的归属。跨项目或跨范式的聚类由服务拒绝。
6. **删除**移除对应 Bot 单元。处理其未完成任务和调度，保护仍在项目中使用或被其他 Bot 引用的资源和成果。聚类和删除都沿用项目已有的权限、数据和任务约束。

## 前端落地

- 沿用 Weave 原生项目侧栏、顶部项目聊天入口、自定义 Bot 标题和底部 Bot 对话输入。在主内容区渲染该单元的唯一排布，关闭旧的通用 Bot 工作台入口及其独立弹窗。通过项目既有入口或范式页面露出需要保留的实验、任务和成果。
- 在现有创建弹窗中用五张可点选的大插图卡表示五个范式，仅保留「名字」输入与取消、创建操作。去掉独立头像、备注、关键词和排布选项。桌面一排五张，窄屏可用三加二换行，给插图留足空间并压紧弹窗留白。
- 五张卡片下方提供「项目扩展范式」。手动扩展时以语义描述说明展示范围、记录时机与组织逻辑，再保存对应的元素名和一种排布。对话中可由 LLM 根据用户的语义描述提交这套定义。定义在项目内复用，使用该定义的 Bot 仍只需选择范式并填写名字。
- 以当前项目源码和界面实现核对复用点。十张示意中的预览翻页属于评审浏览方式，产品页不提供排布切换器。目录、内容标签和优先级用来组织当前排布中的数据。
- 助理和项目主对话顶部隐藏原生子智能体入口。通过 Weave 自己的项目与 Bot 页面呈现分工，现有会话记录继续可查。

## 验收

- 在同一项目创建两个同范式、不同排布的 Bot。各自只有一个主视图和独立的名称、数据范围及会话，通过侧栏可以分别打开。
- 通过对话驱动同范式聚类。侧栏显示统一入口，成员记录和原始出处可追溯。同样操作跨范式时由服务拒绝，已有记录保持可用。
- 通过 Leader 的对话决定或某个 Worker 的结果更新项目进度。其余 Worker 在下一步采用更新后的共享状态。
- 用现有目标依赖、资源、实验审批和运行记录验证至少一条实际交接。前端以真实来源和状态渲染，并按项目约定检查窗口尺寸、缩放和设置组合。
- 分别验证 Bot 插入项目主对话和助手插入 Bot 对话。检查点名、主动发言、原地追问、历史恢复、重复投递与跨项目权限。
