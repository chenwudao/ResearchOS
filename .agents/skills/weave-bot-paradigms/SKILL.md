# Weave 功能 Bot

遵守仓库的 [AGENTS.md](../../../AGENTS.md) 和 [Bot 与项目上下文需求](../../../docs/Bot与项目上下文需求.md)。涉及前端、创建或聚类时，读取 [范式元素与前端参考](references/paradigms.md)，用其中的十个示例检查单个 Bot 的职责、元素和唯一主排布。示例是设计基线。项目可以按实际需求只使用其中部分范式，同范式的实例也可以采用同一种排布。

## 角色与同步

- 全局助手协调明确的项目。项目主对话澄清需求、确定验收标准、分派、处理依赖和验收成果。功能 Bot 是分派时由原生内核运行的子智能体，按职责和继承的项目对话权限执行。Bot 身份、每次原生运行和发起对话的关联可回查。
- 简单查阅与项目决定由项目主对话处理。直接提出和全局转交的执行请求都先按请求登记任务，再把可独立验收的工作分派给 Bot。任务包含目标、输入、验收条件和依赖。宿主按绑定角色限制执行工具，并按请求校验实际分派与成果；覆盖缺少条件和只输出文字的情况。独立任务并发，依赖任务在前置成果验收后启动。
- 项目对话流向同项目所有 Bot 提供相关需求、决定、可公开的工作摘要、进展和成果引用。Bot 接单和进入下一步前读取相关更新，回报进度、阻塞和成果。依据变化时由项目主对话决定延续、修订或暂停，保存与启动下游前校验当前依据。私有推理和工具凭据不得进入事件记录。
- 助手与 Bot 共用同一套插话机制。用户可在当前对话点名有权参与的角色，已参与同一任务的角色也可在有需要用户关注的事项时主动发言。项目主对话协调顺序。插话使用真实发言者，带原消息或任务关联，持续保存在发起任务的对话。按目标对话校验项目权限，并对重复投递去重。
- 项目对话和所有 Bot 通过同一项目范围读取和更新记忆与规则。用项目上下文提供有限的核心要点，再按当前任务主动检索完整记录。用户确认的项目规则按 `rule` 类别保存并置顶，复用现有记忆 ID 修订规则。全局助手查自己的记忆，项目回查采用对话已明确的项目。
- 用户与 LLM 在对话中确定项目需要哪些范式、每类有几个 Bot 及各自的职责。职责匹配且仍适用时复用已有 Bot。需要独立跟踪的职责可以新建。临时交付优先进入已有职责匹配的 Bot。

## 从对话决策到一个功能 Bot

1. 从任务目标、明确约束、相关记忆和最新项目进度提取决定。决定至少含目标项目、操作、范式、Bot 名称、职责范围、一个主排布，以及支撑该排布的任务元素和来源。根据操作带上已有 Bot、成员或成果的引用。
2. 按范式判断元素是否支撑这项任务。由 LLM 组装经过校验的结构化元素，前端用对应的项目组件渲染。信息不足时保留待补，或选一种当前信息能支撑的排布。运行状态、审批、时间、证据和文件来源分别取自有权访问的真实记录。
3. 在项目服务校验范式、排布、元素、项目归属和引用。保存 Bot 的稳定 ID、范式和单一排布。普通任务更新内容；聚类、职责变化等明确的组织决定可以重新确定主排布。
4. **创建**从一个独立 Bot 开始。手动入口沿用项目侧栏创建方式，只收集所选范式和名字，LLM 根据对话与项目上下文决定职责、排布及初始元素。
5. **聚类**把几个同项目、同范式的小 Bot 组织成一个同范式的大 Bot。决定中给出成员、承接 Bot、聚合职责、一种排布和元素归并方式。聚合后以大 Bot 作为统一入口，保留成员身份、来源、对话与已产生的记录引用。按稳定引用去重，归并前厘清未完成任务和定时跟踪的归属。跨项目或跨范式的聚类由服务拒绝。
6. **删除**移除对应功能 Bot。处理其未完成任务和调度，保护仍在项目中使用或被其他 Bot 引用的资源和成果。聚类和删除都沿用项目已有的权限、数据和任务约束。

## 前端落地

- 沿用 Weave 原生项目侧栏、顶部项目对话入口、自定义 Bot 标题和底部 Bot 对话输入。在主内容区渲染该 Bot 的唯一排布，关闭旧的通用 Bot 工作台入口及其独立弹窗。通过项目既有入口或范式页面露出需要保留的实验、任务和成果。
- 按所属任务和 Bot 将工作摘要、文字、结构化图表、实验进度和项目文件引用更新到画布。使用稳定卡片身份及有序事件更新，明确待核验、等待、失败和已保存状态。刷新与重连后补齐更新，聚类后保留实际成员来源。
- 分支和前置依赖绘制从上游到下游的箭头，普通关联用无方向的虚线。同一聚类内允许跨成员关联已保存的卡片，服务核验归属与方向关系。工程台的实验卡片沿用已有实验记录及其登记的可视化数据源，概览和详情随存入的状态与指标刷新。
- 发布有关联的草稿时，先发布上游卡片，再在下游卡片提交 `parentId`、`dependsOn` 或 `relatedIds`。草稿引用同次任务返回的卡片 ID，或本 Bot 与同聚类的已保存卡片。多卡交付在结构化结果填写 `publishDraftIds`，宿主按原会话写入权限保存选定草稿及其引用的草稿，并把连接端点改为正式卡片 ID。原发起对话可在用户确认交付后用 `labweave_bot_publish_drafts` 重试已有草稿。
- 每张画布卡片围绕一个发现、决定、结果或阶段进展。用短标题和一两句纯文本 `summary` 作概览，将可独立阅读的短篇 Markdown 正文写入 `text` 或分派结果的 `answer`。正文先给结论，再按需要写证据、方法、局限或下一步。来源、日期、附件和结构化图表使用各自字段。通用约定适用于五个内置范式及项目扩展范式。
- 分派的 `publicTask` 写给项目成员阅读，完整执行参数写入 `task`。分派结果、进展卡片和 Bot 直接回复均用 Markdown 加粗关键结论，就近标明支持该结论的材料。项目记录用可读名称和 `weave-record:` 引用，原文用可核查的网页链接。发布卡片时也可用 `sources` 提交同项目记录或命名原文链接，产物沿用文件字段。记录 ID、卡键、工具回执留在运行记录里。
- 验收条件写成用户可观察的结果，例如「画布中可查看八张正式卡片，每张卡片都能打开来源」。内部工具名、接口参数及调用要求写在执行指令中。对话、画布和执行过程用可理解的操作描述。历史内容按同一规则展示。
- 在现有创建弹窗中用五张可点选的大插图卡表示五个范式，仅保留「名字」输入与取消、创建操作。去掉独立头像、备注、关键词和排布选项。桌面一排五张，窄屏可用三加二换行，给插图留足空间并压紧弹窗留白。
- 五张卡片下方提供「项目扩展范式」。手动扩展时以语义描述说明展示范围、记录时机与组织逻辑，再保存对应的元素名和一种排布。对话中可由 LLM 根据用户的语义描述提交这套定义。定义在项目内复用，使用该定义的 Bot 仍只需选择范式并填写名字。
- 以当前项目源码和界面实现核对复用点。十张示意中的预览翻页属于评审浏览方式，产品页不提供排布切换器。目录、内容标签和优先级用来组织当前排布中的数据。
- 助手和项目主对话顶部隐藏原生子智能体入口。通过 Weave 自己的项目与 Bot 页面呈现分工，现有对话记录继续可查。

## 验收

- 在同一项目创建两个同范式、不同排布的 Bot。各自只有一个主视图和独立的名称、数据范围及对话，通过侧栏可以分别打开。
- 通过对话驱动同范式聚类。侧栏显示统一入口，成员记录和原始出处可追溯。同样操作跨范式时由服务拒绝，已有记录保持可用。
- 通过项目主对话的决定或某个 Bot 的结果更新项目进度。其余 Bot 在下一步采用更新后的共享状态。
- 对同一类科研执行请求分别验证主对话直接接收与全局转交。用模拟模型尝试直接运行工具和只回复「已完成」，确认宿主约束生效。打开进行中的 Bot 画布查看阶段文字、图表与文件，核对项目归属、状态和重连后的顺序。
- 用现有目标依赖、资源、实验审批和运行记录验证至少一条实际交接。前端以真实来源和状态渲染，并按项目约定检查窗口尺寸、缩放和设置组合。
- 分别验证 Bot 插入项目主对话和助手插入 Bot 对话。检查点名、主动发言、原地追问、历史恢复、重复投递与跨项目权限。
