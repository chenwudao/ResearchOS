# Weave 固定项目 Worker

依据用户于 2026-11-20 确认的新要求，项目统一采用五个固定 Worker。本规则替代以前按需创建、扩展范式、聚类和临时 Bot 自动归档规则。

| Worker | 固定主视图 | 内容职责 |
| --- | --- | --- |
| A 目标 | checklist | 待办、备忘录、优先级、完成条件与进度 |
| B 笔记 | library | 分类资料、来源、摘录、更新跟踪 |
| C 思维导图 | graph | 文献关系、历史脉络、研究范式及依据 |
| D 点子 | branches | 基于项目记忆与实时进度迭代可尝试操作、假设和最小验证 |
| E 工程台 | sequence | 代码、实验、真实运行状态、日志、指标和可视化产物 |

- 新旧项目都必须出现五个永久入口，各一个；稳定 ID、名称、类型和主视图不由模型决定。
- LLM 可读写记录、任务和已确认的项目记忆；不可增删、改名、归档或聚类 Worker。重复创建兼容调用只能返回已有 Worker。
- 任务完成、失败或取消只改变任务和内容状态。严禁交付后自动移除 Worker。
- 老的额外 Bot 保留原数据、布局与会话，在“历史 Bot”入口访问，不能静默丢弃或迁移其记录 ID。
- Leader 使用固定职责分派任务，Worker 读取共享项目状态、相关记忆和当前进度，按原权限执行。工程台保存实际环境、代码、日志、指标和产物。
- 前端保持五种不同的主视图与原生聊天，隐藏结构编辑入口；内容编辑与删除仍可用。
- [范式元素参考](references/paradigms.md)中的示例用于组织内容，不再用于创建多个 Bot 或让模型选择布局。
- 验证新项目五角色、旧记录和会话保留、结构操作服务端拒绝、完成后不归档、刷新及重启稳定、跨项目隔离，以及桌面/窄屏/缩放下的五种页面。
